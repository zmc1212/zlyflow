# 企业批量账号与成员额度上限实施计划

日期：2026-11-19
范围：管理设置 → 账号管理 / 企业管理；仅桌面端。

## 1. 摘要

本轮交付两件事：

1. **企业批量开号**：在「管理设置 → 账号管理」新增「批量新增」入口，选择企业后按「账号前缀 + 连续序号 + 统一初始密码」一次创建最多 200 个员工账号（默认 100），创建成功后弹窗展示并支持复制、下载 CSV。
2. **企业成员额度上限**：在「企业管理 → 企业详情 → 成员与用量」为每个成员设置「不限制 / 每月 / 累计」积分上限；成员消费企业钱包时同时校验企业余额与个人额度，超额返回 402 并给出明确提示。默认不限制，保持既有行为。

用户提出的「企业购买后积分充到企业额度、个人只消耗企业额度」**当前代码已经实现**，本轮不重做计费路由，只补成员级额度管控与批量开号（见第 2 节现状核对）。

### 2.2 对标即梦团队版

- 团队版与个人版相互独立，按席位/成员统一管理，成员使用团队共享资产。
- 团队积分「集中充值、按需分配」：管理员统一充值到团队积分池，再按成员/用途分配，成员消费走团队积分而非个人积分。
- 成员账号由团队管理员创建/导入，成员无需自己充值。

对本项目的映射：企业钱包 = 团队积分池（已有）；本轮新增「按成员分配额度」；批量开号 = 团队席位批量创建。在线支付/套餐订单本轮不做。

## 3. 方案设计

### 3.1 A. 企业批量创建账号

#### 交互

- 账号管理页头部按钮区，在「新增账号」左侧新增「批量新增」按钮（`ListPlus` 图标，默认按钮样式）。
- 弹窗「批量新增企业账号」字段：
  1. 所属企业（`TreeSelect`，必填；默认取当前左侧树选中的企业；停用企业不可提交）。
  2. 登录账号前缀（必填，1-40 位，字母/数字/点/下划线/短横线；提交时转小写）。
  3. 起始序号（`InputNumber`，默认 1，最小 1，最大 999999）。
  4. 创建数量（`InputNumber`，默认 100，1-200）。
  5. 姓名前缀（默认「员工」，1-40 位）。
  6. 统一初始密码（`Input.Password`，6-128 位）。
  7. 实时预览：「将创建 `xh001` ~ `xh100`，共 100 个员工账号，初始密码统一，首次登录需修改」。
- 提交成功后弹窗切换为结果视图：
  - 显示企业、数量、账号范围、初始密码（仅本次展示）。
  - 「复制账号密码」：按 `账号\t密码` 每行一条写入剪贴板。
  - 「下载 CSV」：列 `登录账号,姓名,初始密码,所属企业`，UTF-8 BOM + CRLF，文件名 `企业名-批量账号-YYYYMMDDHHmm.csv`。
  - 明确提示「初始密码只在此处展示一次，请立即下载或复制」。
- 关闭弹窗后刷新 `admin-users` 与 `admin-enterprises`。

#### 生成规则（决策）

- 序号补零宽度：`width = max(3, len(str(start_index + count - 1)))`。
- 登录账号：`f"{prefix.lower()}{index:0{width}d}"`；例如 `xh` + 1..100 → `xh001`…`xh100`。
- 姓名：`f"{display_name_prefix}{index:0{width}d}"`，例如「员工001」。
- 角色固定 `employee`，`must_change_password=True`，不设置邮箱，全部归属所选企业。
- 单次最多 200 个，批量创建只允许员工角色。

#### API

新增 `POST /api/admin/users/batch`（`mutating_admin_user`，CSRF 保护）：

```json
{
  "enterprise_id": "ent-xxx",
  "username_prefix": "xh",
  "start_index": 1,
  "count": 100,
  "display_name_prefix": "员工",
  "password": "初始密码"
}
```

成功 `201`：

```json
{
  "enterprise_id": "ent-xxx",
  "count": 100,
  "first_username": "xh001",
  "last_username": "xh100",
  "users": [{"id": "...", "username": "xh001", "display_name": "员工001"}]
}
```

错误：

- `404` 企业不存在；`409` 企业已停用；`422` 参数非法（前缀/序号/密码/长度）。
- `409` 账号冲突：全部失败、不创建任何账号，`detail` 列出前 20 个冲突账号，提示调整前缀或起始序号。
- `403` 员工无权调用（沿用 `mutating_admin_user`）。

#### 存储层

- `AuthStore` 新增 `create_users_bulk(...)`：
  - 在单事务内完成冲突预检 + 逐条 INSERT（复用方言安全的 `connection.execute`）。
  - **统一密码只计算一次 `hash_password` 并复用**（scrypt 较慢，避免 100 次哈希）。
  - 插入失败按 `IntegrityError` 兜底转为账号冲突异常。
  - 返回 `public_user` 列表，顺序与序号一致。
- 新增 `BatchUsernameConflictError(ValueError)`，携带冲突用户名列表；端点映射 409。
- 审计：`action="batch_create_users"`，`target_type="enterprise"`，`target_id=enterprise_id`，`detail="count=100,range=xh001-xh100"`。

### 3.2 B. 企业成员额度上限

#### 数据模型

新增表 `enterprise_member_quotas`（每个企业 + 成员一行）：

```sql
CREATE TABLE IF NOT EXISTS enterprise_member_quotas (
    enterprise_id VARCHAR(64) NOT NULL,
    user_id VARCHAR(64) NOT NULL,
    period VARCHAR(16) NOT NULL DEFAULT 'none',  -- none / monthly / total
    credit_limit INTEGER NOT NULL DEFAULT 0,
    updated_at VARCHAR(64) NOT NULL,
    PRIMARY KEY (enterprise_id, user_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

- 新增 `sql/031_enterprise_member_quota.sql`。
- `backend/app/storage.py` 的 `initialize()` 同步 SQLite DDL（`CREATE TABLE IF NOT EXISTS`）。
- 新表独立，不改 `users` / 企业钱包表。

#### 计算口径（决策）

- `period=none` 或没有配置行：不限制（默认，兼容现状）。
- `period=monthly`：统计**北京时间（UTC+8）自然月**内该成员在该企业的 `consume - refund` 净消耗；跨月自动归零。
- `period=total`：统计该成员在该企业内的累计 `consume - refund` 净消耗。
- 使用 `enterprise_credit_transactions` 按 `(enterprise_id, user_id)` 聚合，不额外维护「已用」字段，退款天然回冲额度。
- 额度单位为积分（100 积分 = 1 元），与现有钱包一致。

#### 强制执行点（决策）

- 在 `JobStore._route_credit_delta()` 中，当 `type == "consume"` 且结算钱包为企业时，先执行 `_assert_enterprise_member_quota(connection, enterprise_id, user_id, amount)`。
  - 该函数先对 `enterprise_credit_accounts` 行做 `FOR UPDATE`（与余额检查共用同一串行化点），再读取额度与当月/累计已用。
  - 覆盖视频/生图任务预扣（`deduct_credits`）与 LLM/VLM 按次扣费（`adjust_credit`）。
- `CreditService.require_call_balance()` 增加成员额度预检（`store.check_member_quota(user_id, cost)`），避免算力已消耗后才拒绝。
- 退款不校验额度，自动回冲已用。
- 新增 `EnterpriseMemberQuotaExceededError(CreditInsufficientError)`：
  - 复用现有所有 `except CreditInsufficientError → 402` 处理器，无需改十几处端点。
  - 消息示例：「本月企业分配额度不足：上限 5,000 积分，已用 4,800 积分，本次需要 500 积分，请联系企业管理员调整额度」。
  - 永远不因额度拒绝企业充值/调整/退款。

#### API

- `GET /api/admin/enterprises/{id}/members`：响应新增
  - `quota_period`、`quota_limit`、`quota_used`、`month_consumed`。
  - 无配置行返回 `none / 0 / 0 / 当月消耗`。
- `PUT /api/admin/enterprises/{id}/members/{user_id}/quota`：

```json
{ "period": "monthly", "credit_limit": 5000 }
```

  - `period` ∈ `none | monthly | total`；`period != none` 时 `credit_limit` 必须 ≥ 1，≤ `MAX_CREDIT_AMOUNT`。
  - 校验成员确属该企业；管理员只能管理员工（沿用现有规则）。
  - 返回 `{ user_id, enterprise_id, quota_period, quota_limit, quota_used, month_consumed }`。
  - 审计：`action="set_enterprise_member_quota"`。

#### 生命周期清理

- 成员「移出企业」或改绑其他企业时，删除原企业下的额度行，避免回到原企业时继承旧额度。
- 删除企业时一并删除该企业额度行。
- 不删除历史流水；额度用量仍按流水统计。

#### 前端

- `frontend/src/credits/credits.ts`：
  - 新增 `EnterpriseMemberQuotaPeriod = "none" | "monthly" | "total"`。
  - `EnterpriseMember` 增加 `quota_period`、`quota_limit`、`quota_used`、`month_consumed`。
- 企业详情「成员与用量」表格：
  - 新增「额度」列：`不限制` / `每月 5,000（本月已用 1,200）` / `累计 5,000（已用 1,200）`；用尽时红色提示。
  - 操作列新增「额度」按钮，打开 `MemberQuotaModal`。
  - 表头提示：额度只约束成员消费，不改企业钱包余额；退款自动回冲。
- 新增 `frontend/src/admin/MemberQuotaModal.tsx`：
  - `Segmented`：不限制 / 每月 / 累计。
  - `InputNumber`：积分上限，禁用条件为「不限制」；提示 100 积分 = 1 元。
  - 展示当前企业余额、当月已用、累计已用。
  - 保存后刷新 `admin-enterprise-members`，`message.success`。
- 沿用 Ant Design 组件与现有管理后台视觉，不新增 UI 依赖，不新增独立主题状态。

## 5. 假设与决策

1. 批量创建只创建员工账号；管理员/超管仍走单账号入口。
2. 批量创建必须选择启用中的企业；不提供平台内部账号批量创建。
3. 批量创建为**全有或全无**：任一账号冲突则整批不创建，返回冲突列表。
4. 单批上限 200（覆盖 100 的场景，避免一次请求过大）；账号名至少 3 位、最多 64 位；姓名最多 80 位。
5. 统一初始密码只哈希一次；明文只在创建成功弹窗展示，不写日志、不落库。
6. 额度默认不限制；月度按北京时间自然月；累计为加入该企业后的全部净消耗。
7. 额度错误复用 402（沿用 `CreditInsufficientError` 语义），不新增 HTTP 状态。
8. 换绑/移出企业清除原企业额度设置；删除企业清理额度行。
9. 本轮不做：企业管理员自助后台、在线支付/订单、企业品牌定制、CSV 名单导入、成员额度批量分配。
10. 仅做桌面端；不新增移动端适配。

## 9. 风险与回滚

- **风险：额度校验影响既有任务提交**。默认 `none` 且无配置行即不限制；只有管理员显式设置后才生效。
- **风险：月度边界与服务器时区不一致**。统一固定 UTC+8 计算，不依赖部署机时区。
- **风险：批量建号哈希耗时**。统一密码只哈希一次，单事务插入。
- **风险：并发消费绕过额度**。额度检查与钱包变更在同一事务，并以企业钱包行锁串行化；`require_call_balance` 再做一次前置预检。
- **回滚**：`git revert` 本轮提交；`DROP TABLE IF EXISTS enterprise_member_quotas` 即可关闭额度能力；批量接口删除后账号表结构无变化。企业钱包、模型策略与既有计费路径零改动。
