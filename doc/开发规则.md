# 开发规则

1. **配置信息管理**：修改数据库、Redis 或相关中间件连接信息时，统一前往项目根目录下的 `.env` 文件中配置与获取（模版参考 `.env.example`）。
2. **SQL 文件管理**：如果有 SQL 修改，请在项目根目录下的 `sql` 目录中新增或修改相应的 SQL 文件。
3. **数据库执行**：直接远程连接数据库执行相应的 SQL 修改（连接信息参照 `.env` 文件）。
4. **通知用户**：在完成数据库修改后，明确告知用户已经修改了数据库。
5. **修改记录**：每次修改完成后，将本次修改的思路整理到项目根目录下的 `dev-log/修改记录.md` 文件中，按 **修改时间** 分类归档（同一天的修改归入同一个日期标题下），记录格式包含：修改标题、功能模块、修改原因及实现思路。
6. **本地开发与测试**：数据为线上数据，开发阶段的所有测试均在本地启动测试，包括服务端和后台应用，仅数据库使用线上的。
7. **报错修复**：每次出现报错修复时，需要再列出错误原因，和修复方案，确保其他用户也能快速定位并修复。并已更新修改记录。
8. **后端技术栈**：后端服务统一使用 Python 进行开发，Web 框架指定使用 `fastapi`。
9. **前端技术栈与目录**：前端统一使用 Vue 3 进行开发，所有前端工程及代码文件统一存放在项目根目录下的 `z-admin` 目录中。
10. **数据表建表规则**：所有数据表必须统一以 `ai_` 为前缀进行命名（采用小写加下划线命名法，例如 `ai_comfy_provider_settings`、`ai_grs_provider_settings` 等），禁止创建无前缀或非 `ai_` 前缀的数据表。
