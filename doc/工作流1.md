# 工作流 1：剧集分镜生成 MiniMax H3 多镜头有声视频

## 1. 文档目的

本文说明如何从项目剧集工坊读取 Beat 分镜数据，按 MiniMax H3 Prompt Writing 规则生成提示词，并通过 ComfyUI `MiniMaxH3Director` 一次提交多个镜头，最终输出带对白、环境音、动作音和配乐的视频。

本文既是实现规范，也是后续人工检查和 Codex 执行任务时的操作手册。不要把本文示例中的项目 ID、人物、图片路径或提示词原样用于其他剧集。

## 2. 当前工作流能力

该流程支持：

- 从 `/api/projects/{project_id}/episodes/{episode_id}` 获取剧集与 Beat 数据；
- 按 Beat 顺序生成多段视频，每个 Beat 对应一个镜头；
- 每个镜头传入两张图片：主角造型图和场景图；
- 按 H3 Ref2VA 六段格式生成详细提示词；
- 保留原始对白，并生成口型、动作音、环境音和非叙事配乐；
- 使用 MiniMax H3 Director 在一次 `/prompt` 请求中顺序运行全部镜头；
- 合并镜头为一个 MP4；
- 通过 ComfyUI 队列和历史接口查询状态与结果。

## 3. 系统与接口

### 3.1 业务系统接口

读取剧集详情：

```http
GET /api/projects/{project_id}/episodes/{episode_id}
```

关键响应字段：

```json
{
  "id": "ep-xxx",
  "title": "剧集标题",
  "beats": [
    {
      "id": "beat-xxx-1",
      "sequence": 1,
      "heading": "镜头标题",
      "characters": ["人物名"],
      "character_ids": ["ast-xxx"],
      "scene": "场景名",
      "scene_id": "ast-xxx",
      "props": ["道具名"],
      "action": "动作描述",
      "camera": "运镜描述",
      "dialogue": "原始对白",
      "subtitle": "旁白或字幕",
      "video_prompt_zh": "人工编辑的视频动作提示词",
      "video_duration": "8",
      "render_url": "精绘分镜图 URL"
    }
  ]
}
```

提示词字段取值优先级：

```text
动作：video_prompt_zh > action
场景：scene > heading 中的场景信息
对白：dialogue，必须原文保留
旁白：subtitle 或显式旁白字段，没有数据时不得编造剧情旁白
时长：请求参数 > video_duration > 系统默认值
```

### 3.2 ComfyUI 接口

```http
GET  /system_stats
GET  /object_info/MiniMaxH3Director
POST /upload/image
POST /prompt
GET  /queue
GET  /history/{prompt_id}
GET  /view?filename=...&subfolder=...&type=output
POST /interrupt
WS   /ws?clientId={client_id}
```

在提交前，应从 `/object_info/MiniMaxH3Director` 动态读取 `task_type` 等枚举值。不要手写包含中文和长破折号的枚举后再经过未知编码的 Shell 转发。

## 4. 前端工作流与 API 工作流的区别

用户导出的 ComfyUI JSON 通常是画布格式，包含：

- `nodes`
- `links`
- `widgets_values`
- 节点位置、尺寸、分组和前端状态

此格式不能直接提交给 `/prompt`。`POST /prompt` 需要 API 格式：

```json
{
  "client_id": "业务唯一客户端 ID",
  "prompt": {
    "1": {
      "class_type": "UNETLoader",
      "inputs": {
        "unet_name": "模型文件名",
        "weight_dtype": "default"
      }
    }
  }
}
```

禁止仅按 `widgets_values` 下标机械转换。Director 带有复杂自定义 UI 状态，应根据 `/object_info` 中的输入名称构造 `inputs`。

## 6. 生成模式选择

### 6.1 Ref2VA / r2v

适合使用人物造型、场景、道具等多张参考图生成镜头。本文的“两张图”方案使用：

```text
task_type = r2v — 参考主体生视频(Reference to Video)
```

图片是参考资产，不一定是视频的第一帧。提示词必须使用 `<Picture N>` 和 `<Subject N>` 说明图片的职责。

### 6.2 I2VA / i2v

若要求精绘分镜图严格作为视频 0 秒第一帧，应使用 i2v，并采用技能中的第一帧指令。不能把“场景参考图”和“首帧锚点”混为一谈。

### 6.3 选择原则

- 人物造型图 + 场景参考图：优先 r2v；
- 一张精绘图作为明确首帧：优先 i2v；
- 明确首尾两帧：使用 fl2v；
- 以已有视频为时间线进行编辑：使用 v2v/rv2v；
- 不传图片：使用 t2v。

## 7. 每镜头两张参考图规则

每个镜头固定传入：

```text
<Picture 1>：该镜头主角的正确造型图
<Picture 2>：该镜头对应的场景图
```

时间线中的引用格式：

```json
"refs": [
  {
    "index": 0,
    "imageFile": "project/episode/character-look.png",
    "fileName": "character-look.png",
    "type": "input",
    "subfolder": "project/episode"
  },
  {
    "index": 1,
    "imageFile": "project/episode/scene.png",
    "fileName": "scene.png",
    "type": "input",
    "subfolder": "project/episode"
  }
]
```

`index: 0` 对应 `<Picture 1>`，`index: 1` 对应 `<Picture 2>`。

### 7.1 造型图校验

不能把同一张造型图无条件用于整集。提交前必须检查：

- 时代是否一致，例如现代镜头不能使用古代长衫造型；
- 年龄是否一致，例如 26 岁现代人物和 17 岁古代人物需要不同造型；
- 服装阶段是否一致；
- 发型、妆容、伤势和随身物品是否符合该 Beat；
- 当前 Beat 没有主角时，不应强制把主角生成到画面中。

若一个镜头有两名必须锁定身份的人物，两图限制不足以同时提供“两个角色造型 + 场景”。此时必须选择以下一种方案：

- 增加参考图数量；
- 使用包含两人且身份清晰的组合造型图作为 `<Picture 1>`；
- 仅锁定主角，其他人物由文本生成，但接受身份稳定性下降。

### 7.2 场景图校验

- 优先使用 Beat 的 `scene_id` 精确查找资产，不要只按中文字符串模糊匹配；
- 场景正面、反打、全景应根据镜头机位选择；
- 同一地点的连续镜头尽量使用同一套场景资产；
- 图片上传后应记录原始 URL 与 ComfyUI `imageFile` 路径，便于审计。

## 8. MiniMax H3 帧数与时长规则

H3 每段帧数必须满足：

```text
frame_count = 17k + 5
```

由秒数转换帧数时，先计算 `round(duration * fps)`，再向上对齐到最近的 `17k+5`：

```text
n = max(5, round(duration_seconds * fps))
aligned = n + ((5 - n % 17) % 17)
```

常见组合：

| 目标时长 | FPS | 每段帧数 | 实际时长 | 说明 |
| --- | ---: | ---: | ---: | --- |
| 5 秒 | 24 | 124 | 5.1667 秒 | 不是精确 5 秒 |
| 5 秒 | 24.8 | 124 | 5 秒 | 精确 5 秒，但非原生 24fps |
| 8 秒 | 24 | 192 | 8 秒 | 推荐，精确且满足 `17k+5` |

多镜头时间线：

```text
segment.start = 前面所有 segment.frameCount 的总和
totalFrames = 所有 segment.frameCount 之和
总时长 = totalFrames / fps
```

6 个 8 秒镜头的标准参数：

```json
{
  "fps": 24,
  "frames_per_shot": 192,
  "shot_count": 6,
  "total_frames": 1152,
  "total_duration_seconds": 48
}
```

对应起始帧为 `0, 192, 384, 576, 768, 960`。

## 9. H3 Prompt Writing 规则

本地技能位置：

```text
source1/app/h3_prompt_writing/SKILL.md
source1/app/h3_prompt_writing/references/ref-en.txt
source1/app/h3_prompt_writing/references/base-en.txt
```

生成提示词前必须完整读取 `SKILL.md`，再按模式读取对应参考文件：

- r2v / Ref2VA：读取 `references/ref-en.txt`；
- t2v、i2v、fl2v、l2v：读取 `references/base-en.txt`。

### 9.1 Ref2VA 固定六段结构

字段名和顺序不可改变：

```text
subject_definitions:

summary:

retention_analysis:

detailed_description:

overall_soundscape:

non_diegetic_music:
```

规则：

- 六个段落主体使用英文；
- 对白、歌词、画面可见文字保留原语言；
- `<Picture 1>`、`<Picture 2>`、`<Subject 1>` 等标签在所有段落中语义必须一致；
- 描述可见和可听的具体内容，不要只写剧情概述；
- 每个镜头都要说明构图、人物位置、环境、光线、动作、状态变化、运镜和声音；
- 单镜头时长必须与提示词描述相符；
- 不得使用未定义的引用标签。

### 9.2 两图 Ref2VA 模板

```text
subject_definitions:
<Subject 1> is [角色名], whose face, hairstyle, age impression, body proportions and current costume are anchored by <Picture 1>.
<Subject 2> is the environment, props, lighting and spatial layout shown in <Picture 2>.
<Picture 1> is the protagonist identity and current-costume reference.
<Picture 2> is the concrete scene reference for [Shot 1].

summary:
[reference generation + audio reference] Generate an eight-second Ref2VA shot using <Picture 1> to preserve the protagonist and <Picture 2> to preserve the scene, with synchronized action, Chinese dialogue or narration, physical sound, ambience and audience-only music.

retention_analysis:
<Subject 1> (appears in [Shot 1]): fully_preserved - preserve the face, hairstyle, age impression, body proportions and current costume from <Picture 1>.
<Subject 2> (appears in [Shot 1]): fully_preserved - preserve scene geometry, key props, lighting direction, color relationships and spatial depth from <Picture 2>.
<Picture 1> ([Shot 1] identity anchor): fully_preserved - import the character identity and costume, not the source background.
<Picture 2> ([Shot 1] scene anchor): fully_preserved - import the location and composition without changing the protagonist design.

detailed_description:
Live-action Chinese cinematic realism with natural skin texture, restrained color, realistic material response and stable temporal motion. [Shot 1] [说明开场构图、人物位置、场景、光线和关键道具]. The camera [运动类型、幅度、速度]. [按发生顺序描述完整动作和反应]. [对白/旁白]. The shot holds long enough for the complete spoken line, then ends on [清晰的动作结果或反应] with stable composition.

overall_soundscape:
[环境底噪、动作接触声、脚步、衣料、呼吸等]. Every physical sound remains synchronized to visible contact and movement.

non_diegetic_music:
[乐器、速度、节奏、强弱变化].
```

注意：普通参考图不属于 `keyframe completion`。只有图片确实充当首帧、末帧或具体关键帧锚点时，才在 `summary` 中使用该任务类型。

## 10. 对白、旁白和声音规则

### 10.1 对白

- 必须原文保留，不翻译、不润色、不删词；
- 使用稳定说话人 ID，例如沈砚始终为 `(S1)`，母亲始终为 `(S2)`；
- 对白格式固定为：

```text
Shen Yan (S1) says in a clear young Chinese male voice with a measured pace: <d>[Chinese] 这里……是什么地方？</d>
```

- `<d>` 内只放语言标签和实际台词；
- 镜头要明确“hold long enough for the complete spoken line”，避免结尾截断；
- 台词较长时应增加镜头时长，而不是强行压缩语速。

### 10.2 旁白

旁白必须来自剧集字段或用户明确提供的文本。格式：

```text
The narrator (S3) says in an off-screen voiceover: <d>[Chinese] 旁白原文。</d> while every on-screen character's lips remain completely closed.
```

规则：

- 必须写 `says in an off-screen voiceover`；
- 紧跟说明画面人物嘴唇保持闭合；
- 同一旁白者在全部镜头中复用同一个 `(Sx)`；
- 没有旁白数据时，不得自行补写剧情旁白。

### 10.3 跨镜头对白

若台词跨剪辑继续，前后两段均使用 `<scenetrans>`，并明确声音连续：

```text
<d>[Chinese] 前半句<scenetrans></d>
<d>[Chinese] <scenetrans>后半句。</d>
```

### 10.4 环境音、动作音和配乐

- 当前镜头内同步发生的声音写入 `detailed_description`；
- 整体环境与物理声音总结写入 `overall_soundscape`；
- 观众能听到、角色听不到的配乐写入 `non_diegetic_music`；
- 配乐应写乐器、速度、节奏和动态变化，不只写“悲伤”“电影感”；
- 完全不需要配乐时使用 `non_diegetic_music: N/A`。

### 10.5 音频模式

生成模型音频必须设置：

```json
"audioMode": "generate"
```

三个有效模式：

| 值 | 行为 |
| --- | --- |
| `generate` | 使用 H3 Audio VAE 生成对白、环境音等 |
| `source` | 使用源视频原声；无源视频时会静音 |
| `mute` | 强制静音 |

仅连接 Audio VAE 不代表一定会生成声音。`audioMode: source` 且没有源视频时，Director 会跳过音频 VAE 解码并输出静音。

## 13. 推荐采样参数

```json
{
  "cfg": 1.0,
  "seed": 888,
  "frame_rate": 24,
  "width": 864,
  "height": 480,
  "ref_max_size": 864,
  "steps": 20,
  "sampler": "res_multistep",
  "scheduler": "simple",
  "shift_video": 12.0,
  "shift_audio": 3.0,
  "clear_vram_between_segments": false,
  "export_source_images": false
}
```

这些参数来自当前加速工作流基线，不是所有硬件的唯一正确值。显存不足时可打开 `clear_vram_between_segments`，代价是段间重新加载导致速度下降。

统一负面提示词示例：

```text
camera shake, identity drift, face drift, age change, hairstyle change,
costume change, inconsistent proportions, extra limbs, bad hands,
broken lip sync, random text, subtitles, watermark, scene drift,
plastic skin, oversaturated colors, low detail
```

负面词应结合画面调整，不要禁止剧情明确需要的动作、文字或视觉效果。

## 14. 提交流程

### 14.1 数据准备

1. 获取剧集详情；
2. 按 `sequence` 对 Beat 排序；
3. 校验镜头数量、时长、对白和旁白；
4. 根据 Beat 的人物、时代和服装选择正确造型图；
5. 根据 `scene_id` 选择正确场景图；
6. 下载图片并通过 `/upload/image` 上传到 ComfyUI；
7. 保存图片原 URL、上传路径和引用编号。

### 14.2 提示词生成

1. 确定模式为 Ref2VA；
2. 为每个 Beat 分别写完整六段提示词；
3. 完整保留对白和旁白原文；
4. 分配并复用说话人 ID；
5. 根据时长安排动作发生顺序、说话节奏和结尾停顿；
6. 添加环境音、动作音和配乐；
7. 校验所有 `<Picture N>`、`<Subject N>` 均已定义。

### 14.3 工作流提交

1. 从 `/object_info` 读取节点输入定义和枚举；
2. 构造 API 工作流；
3. 把 `timeline_data` 序列化为 JSON 字符串；
4. 提交 `POST /prompt`；
5. 必须检查 HTTP 状态、`prompt_id` 和 `node_errors`；
6. `node_errors` 为空只代表入队校验通过，不代表最终执行成功。

提交成功响应：

```json
{
  "prompt_id": "uuid",
  "number": 123,
  "node_errors": {}
}
```

## 15. 状态查询与结果获取

### 15.1 队列状态

```http
GET /queue
```

- 位于 `queue_running`：正在执行；
- 位于 `queue_pending`：等待执行；
- 两处均没有：继续查询 `/history/{prompt_id}`。

### 15.2 历史状态

```http
GET /history/{prompt_id}
```

成功条件：

```text
status.status_str = success
status.completed = true
```

失败时读取 `status.messages` 中的 `execution_error`，重点检查：

- `node_id`
- `node_type`
- `exception_message`
- `traceback`
- `current_inputs`

### 15.3 输出地址

`SaveVideo` 输出一般包含：

```json
{
  "filename": "video.mp4",
  "subfolder": "video/project/episode",
  "type": "output"
}
```

访问格式：

```text
{comfy_base_url}/view?filename={URL编码文件名}&subfolder={URL编码目录}&type=output
```

- [ ] Beat 已按 `sequence` 排序；
- [ ] 每个 Beat 都有非空动作描述；
- [ ] 全部对白逐字保留；

## 17. 常见错误与修复

### 17.1 有画面但没有声音

症状：Director 报告出现：

```text
Audio: source - skip audio VAE decode
Source audio: none - fell back to silent
```

原因：`audioMode` 设置为 `source`，但时间线没有源视频或源音频。

修复：

```json
"audioMode": "generate"
```

### 17.2 中文枚举变成问号

症状：

```text
Task r2v ? ????? is not supported
```

原因：Shell、临时脚本或编码链破坏了 `r2v — 参考主体生视频(Reference to Video)`。

修复：从 `/object_info/MiniMaxH3Director` 动态读取枚举；序列化时间线时可使用 `ensure_ascii=true`，避免中间链路改写 Unicode。

### 17.3 提交成功后立即失败

`node_errors: {}` 仅代表输入校验通过。必须继续查询 `/history/{prompt_id}` 的 `execution_error`。

### 17.4 场景图映射错误

原因通常是按 `heading` 进行脆弱的字符串匹配。

修复：使用 `scene_id` 关联资产；提交前输出每个镜头的 `sequence -> Picture 1 -> Picture 2` 映射供检查。

### 17.5 对白被截断

原因：镜头时长不足、动作过多、台词太晚开始或提示词没有要求完整说完。

修复：

- 增加镜头时长；
- 为 8 秒镜头使用 192 帧、24fps；
- 让对白在动作中前段开始；
- 写明 `complete, unhurried dialogue`；
- 写明镜头在台词结束后保持反应和自然停顿；
- 特别长的台词拆为两个 Beat，而不是强行加快语速。

### 17.6 参考图没有上传完整

远程图片下载可能出现 `IncompleteRead` 或连接中断。应使用流式下载、重试、文件长度检查，并只在图片完整后调用 `/upload/image`。

### 17.7 错误终止其他任务

`POST /interrupt` 可能停止当前 ComfyUI 正在运行的全局任务，不一定只针对某个 `prompt_id`。业务系统多人共用 ComfyUI 时，禁止为了替换自己的任务直接调用全局中断；应优先使用队列删除接口或等待当前任务完成。

## 19. 后续产品化建议

建议把人工/Codex 操作封装为后端接口：

```http
POST /api/projects/{project_id}/episodes/{episode_id}/generate-video
```

请求示例：

```json
{
  "workflow": "minimax_h3_director_ref2va",
  "beat_ids": ["beat-1", "beat-2"],
  "duration_per_beat": 8,
  "fps": 24,
  "width": 864,
  "height": 480,
  "audio_mode": "generate",
  "seed": 888
}
```

推荐模块边界：

- `ComfyWorkflowBuilder`：Beat、资产和参数转换为 API 工作流；
- `H3PromptBuilder`：按技能规则生成并校验提示词；
- `ComfyAssetUploader`：下载、校验和上传参考素材；
- `ComfyJobRunner`：提交、查询、错误解析和结果下载；
- `EpisodeVideoService`：创建业务任务、回写结果并上传对象存储。

任务表应保存：

- 完整请求参数和 API 工作流；
- 每个 Beat 的参考图原 URL 和 ComfyUI 路径；
- 每个 Beat 的完整提示词；
- `client_id`、`prompt_id`、队列号；
- 状态、进度、错误和 Director 运行报告；
- 最终 ComfyUI 输出地址、对象存储地址和完成时间。

## 20. 核心原则摘要

1. 先理解 Beat 数据，再选择模式和资产；
2. 前端工作流 JSON 必须转换为命名输入的 API 工作流；
3. Ref2VA 提示词严格遵守六段结构；
4. `<Picture 1>` 和 `<Picture 2>` 的职责必须明确且一致；
5. 对白、旁白原文保留，声音类型各归其位；
6. 需要模型声音时必须使用 `audioMode: generate`；
7. 时长和帧数同时满足业务要求与 `17k+5` 约束；
8. 提交成功不等于执行成功，必须检查历史结果；
9. 所有镜头映射在提交前输出并人工或程序校验；
10. 不要将一次生成的项目 ID、图片和造型规则硬编码为通用规则。
