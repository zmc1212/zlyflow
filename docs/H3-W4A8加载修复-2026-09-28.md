# H3 W4A8 模型加载修复

日期：2026-09-28。范围：解决复制工作流中节点 23 的 `KeyError: asym_w4a8_int8`，保留原模型、原 Director 和原工作流。

## 根因

实际实例 `http://192.168.10.54:8188` 使用 `D:\ZlyFlow-ComfyUI-Portable-20260827-152136\python310\python.exe`。模型在 `D:\ComfyUI-Models\diffusion_models\minimax_h3_ref2va_pruned_w4a8_mixed.safetensors`，大小 12,540,858,008 字节，元数据声明 `asym_w4a8_int8`。不是缺文件。

环境是 PyTorch `2.11.0+cu128`、RTX 4080、comfy-kitchen `0.2.26`。现有 ComfyUI `quant_ops.py` 未注册该格式，旧厨房库也没有对应 layout。普通 UNETLoader 因而在加载权重时报 KeyError。

## 修复方案与来源

上游 [comfy-kitchen PR 90](https://github.com/Comfy-Org/comfy-kitchen/pull/90) 已合并 W4A8 支持；当前 PyPI `0.2.35` 提供 CPython 3.10 Windows wheel，不再需要照旧第三方文档自行编译 Linux 内核。

- Windows wheel：`comfy_kitchen-0.2.35-cp310-cp310-win_amd64.whl`，SHA-256 `eaee40b90b6996c9054ff5fd3cdf524613b759d49099047042c20d9d77276ad8`。
- 专用加载节点来自 [starsFriday/ComfyUI-W4A8-Loader](https://github.com/starsFriday/ComfyUI-W4A8-Loader/tree/ad1d4e072bd2ed5eec1d30d07ec390f327a3af52)，固定提交 `ad1d4e072bd2ed5eec1d30d07ec390f327a3af52`，注册类 `ExperimentalW4A8UNETLoader`。
- 安装至现有 `Comfyui/custom_nodes/ComfyUI-W4A8-Loader`；不覆盖原 Director 或 ComfyUI 核心文件。只在新副本中把节点 23 改为专用加载器，保留原 unet_name、MODEL 输出接线、LoRA 与采样参数。旧 `director_refine_accel` 基线不变。
- 依赖及源码哈希锁定于 `comfyui_nodes/w4a8-loader.lock.json`。不升级 PyTorch，不安装额外模型。
- 检查过 bootstrap/portable-manifest.json，仅固定 pillow、triton-windows、sageattention；没有固定 comfy-kitchen，无需修改启动器或清单。
