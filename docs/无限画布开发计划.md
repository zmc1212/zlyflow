## 1. 目标与边界

### 1.1 产品目标

在 ZLY AI Video Studio 内提供一张可长期使用的无限画布，用来组织分镜、提示词、参考图和生成结果，并逐步与现有任务系统打通：

- 用画布整理创作思路，而不是只做一次性生成表单。
- 画布上的图片/视频可以直接来自作品库或生成任务，结果也能回到画布。
- 保持账号隔离、双主题、桌面端体验和现有任务/存储架构不变。

参考对象：

- WorkRally Canvas Manager（`https://workrally.qq.com/toolbox/canvas-manager`）：只做只读交互分析，不创建、删除或修改其真实画布。
- `https://github.com/morluto/rea`：参考其画布交互与状态组织方式。

### 1.2 明确不做

- 不新建第二套任务队列、ComfyUI 或模型配置；生成一律复用现有 `POST /api/jobs` 与后台 worker。
- 不替换导演台、剧集工坊或作品库，画布是并列的工作区入口。
- V0–V2 不做多人实时协作、分享权限和移动端适配；这些放到 V5 及以后。
- 不把 ComfyUI 技术参数直接暴露给普通用户；工作流参数仍以 `workflow_registry.py` 的 `ui_group` 为准。

## 3. 已完成能力与验证基线

### 3.1 V0（最小可用画布）

- 画布列表支持新建、打开、重命名、删除；删除会级联清理草稿和历史版本。
- 编辑器支持文字、图片、画板三类节点；可拖动、删除、连线、缩放、平移，带 MiniMap 和缩放控件。
- 文字节点双击编辑；画板可调整尺寸和标题；图片地址只接受 `http(s)`、站内路径或 `data:image/`。
- 自动保存：变更后 1.2 秒防抖写入；顶部显示「保存中 / 已保存 / 待保存 / 重试中 / 保存失败 / 版本冲突」。
- 保存使用 `base_version` 乐观锁；409 时暂停自动保存并提示加载服务器最新版本，不覆盖他人内容。
- 历史版本可查看最近版本并恢复；恢复会写成新的当前版本，不覆盖历史。

### 3.2 V1（编辑效率与素材复用）

- 撤销/重做：350 毫秒防抖快照，最多 50 步；新操作会截断重做分支。
- 快捷键：`Ctrl/Cmd+Z` 撤销、`Ctrl/Cmd+Shift+Z` 或 `Ctrl/Cmd+Y` 重做、`Ctrl/Cmd+D` 复制选中节点。
- 复制节点：位置偏移 32px，复制当前节点的数据快照。
- 作品库插入：懒加载 `GET /api/library`，按图片/视频分组，过滤 `local` 与 `expired` 条目，最多展示 80 项。
- 素材 URL 优先级：`cloud_url` → `/api/media/{path}` → `download_url`。
- 插入的节点保留 `assetPath` 与 `sourceJobId`，便于后续追溯到作品库或生成任务。
- 视频节点：静音循环预览、播放按钮、双击/按钮打开预览弹窗；图片节点双击预览。
- 双主题：浅色/暗色均使用 `colorMode`、`--studio-*` 语义变量和 Ant Design token。

### 3.3 V2.1（节点模型与兼容层）

- 草稿写入 `schemaVersion`（当前为 2）；旧 V0/V1 草稿缺省按 1 读取，首次保存后升级为 2。
- `serializeCanvasDraft` 现在保留 `canvasSettings`、节点 `zIndex`、宽高、父级、扩展和拖拽等必要字段；历史快照与服务器保存共用同一序列化入口。
- 加载时把未注册的节点类型归一为 `unknown` 节点，并把原始类型存入 `data.originalType`；保存时还原原始 `type` 并从 `data` 中移除该字段，因此新旧版本互开不会丢节点或业务数据。
- `unknown` 节点渲染为可拖动、可删除的提示卡，显示原始类型并说明内容已保留；左右连线句柄保留，关联边不会消失。
- 解析时修复缺失或非法的 `position`、`data`（回落到 `{x:0,y:0}` 与 `{}`），并过滤缺少字符串 `id` 的节点；不做阻断式字段校验，URL 协议仍在交互入口校验。
- 编辑器注册 `unknown` 节点类型；复制、删除、撤销/重做和自动保存对未知节点与普通节点一致。

验收结果：旧 V0/V1 草稿正常打开；含 `generator` 未知类型的草稿在拖动后自动保存仍保留原类型、`data`、`canvasSettings` 与 `zIndex`；删除未知节点会同时清理关联边，`Ctrl/⌘ Z` 可恢复。

### 3.4 V2.2（多选、对齐与连线管理）

- 选择状态由单个 `selectedId` 改为 `selectedNodeIds` + `selectedEdgeIds`，通过 `useOnSelectionChange` 同步 React Flow 的原生选择；工具栏、删除和复制都按当前选择集合工作。
- 多选沿用 React Flow 默认键位：`Ctrl/⌘ + 点击` 追加/取消节点，`Shift + 拖拽` 框选；点击空白清空选择。画布底部提示和快捷键 Popover 已按实际键位改写，不再使用错误的多选说明。
- 多选复制调用 `duplicateCanvasSelection`：全部选中节点偏移 32px，只复制两端都在选择内的边（内部连线），新边 ID 通过 `buildEdgeId` 重新生成；复制结果替换当前选择，可继续拖动或再次复制。
- 多选删除同时清理选中节点关联的所有边；选中边可单独删除，不影响节点；`Delete`/`Backspace`、工具栏删除按钮和撤销/重做均覆盖以上两种删除。
- 工具栏新增「对齐与分布」下拉：左对齐、水平居中、右对齐、顶部对齐、垂直居中、底部对齐、水平等距、垂直等距。对齐按所选节点包围盒计算；分布少于 3 个节点时禁用。执行前调用 `flushHistory`，因此一次对齐就是一步可撤销操作。
- 对齐/分布/复制是 `canvas-model.ts` 中的纯函数：`alignCanvasNodes`、`distributeCanvasNodes`、`duplicateCanvasSelection`。节点尺寸优先取 `measured.width/height`，其次 `style.width/height`，最后节点顶层 `width/height`；尺寸未知时按 0 处理，不阻断操作。

### 3.7 V2.5（保存可靠性与性能）

- 保存状态机扩展为 `saved | dirty | saving | retrying | error | conflict`，顶部状态标签新增「重试中」。保存失败后按 2 秒、5 秒、10 秒指数退避自动重试，最多 3 次；重试期间继续编辑不会丢失内容，卸载或重新加载会清理计时器。手动点「保存」会立即重试。
- 仅对可恢复错误重试：非 `ApiRequestError` 的网络异常、5xx、408 和 429；其它 4xx 直接进入 `error`，409 冲突仍立即暂停自动保存并显示「加载最新版本」，不进入重试队列。
- 体积提示：保存前用 `TextEncoder` 计算 UTF-8 字节数。达到 6 MB 显示警示条「画布体积约 X MB，接近 8 MB 上限」；超过 8 MB 时拒绝保存、显示错误条「画布体积约 X MB，超过 8 MB 上限」且不重试，提示删除大型内嵌图片或改用素材地址。手动保存同样受此限制，不会静默失败。
- 大画布性能：节点数超过 300 时启用 React Flow `onlyRenderVisibleElements`，只渲染视口内节点；仅影响 DOM 渲染，不改节点数组、历史或保存内容。官方 MiniMap、选择、拖拽和连线仍作用于完整节点集合。
- 视口持久化：`canvasSettings.viewport` 记录 `{x, y, zoom}`，在 `onMoveEnd` 时以 0.001 精度写回；坐标变化小于 0.5px、缩放变化小于 0.001 时忽略，避免抖动。刷新后若存在合法视口则作为 `defaultViewport` 并关闭 `fitView`，否则回退到自动适配；缩放范围显式固定为 0.1–2。恢复历史版本时保留当前实时视口，不会被历史视口拉走；无合法视口时不会写入。
- 视口改动会让画布进入待保存状态，随下一次防抖自动保存写入；首次打开没有视口记录的画布时，`fitView` 会产生一次视口保存，因此可能多出一个历史版本（已知限制，功能无影响）。
- 纯逻辑抽到 `canvas-save.ts`：重试延迟/可重试判定、409 版本解析、保存状态转换、UTF-8 体积与阈值、体积格式化、虚拟化阈值；视口的读取与变更判断在 `canvas-model.ts`。组件只负责计时器、请求和 UI 接线。
- 单测覆盖：`canvas-save.test.ts` 8 项（重试序列、可重试错误、409 解析、状态转换、UTF-8 体积、6/8 MB 边界、格式化、300 节点阈值）；`canvas-model.test.ts` 新增 2 项视口测试（合法/非法/越界读取、亚像素噪声）。

验收结果：隔离环境（Vite 5174 + SQLite 后端 7866，局域网地址）实测断网后保存进入「重试中（2/3）」，恢复网络后下一次退避自动保存成功，无需手动操作；超过 8 MB 的画布添加节点后显示显式错误且等待 7 秒未重试；6.2 MB 画布显示体积预警；409 时标签为「版本冲突」、自动保存暂停，点击「加载最新版本」后回到服务端内容且版本未额外递增。301 节点画布在缩放到局部后仅渲染 80 个节点 DOM（MiniMap 仍为 301 个），点击可选中并打开检查器；使用独立无头 Chrome 通过 CDP 原生鼠标事件拖动节点，位置由 (900,520) 变为 (1040.75,607.30)，自动保存后版本 4→5，草稿持久化新坐标。视口刷新前后均为 `translate(-51.765px, -179.967px) scale(1.631)`，未产生多余保存；浅色与暗色下预警/错误条、状态标签对比度正常，控制台无错误。

### 3.10 V3.2（提示词与参考图连线）

- 文字节点→提示词：指向生成节点的文字节点按画布边数组顺序去重收集，非空文本以空行拼接成生效提示词；生成节点自身的手动提示词只在没有任何文字来源时使用。已连接但内容为空的文字节点会阻断提交，并在节点卡片、浮动工具栏和属性面板给出同一原因，不再静默忽略。
- 参考图语义：图片与带安全 URL 的生成结果节点作为参考图，严格按入边数组顺序编号 1..n 提交，同一节点只提交一次；连线顺序即 `<Picture n>` 顺序，不另存排序字段。
- 连线即时校验：`isValidConnection` 允许文字、图片和生成结果连入生成节点，图片/视频结果节点只接受生成节点来源；切换工作流后立即按 `min_references`/`max_references` 计算「支持 1-9 张参考图，当前 0 张」等提示。数量不满足时卡片的生成按钮、浮动工具栏和检查器提交按钮同步禁用，提示文案一致；不满足只阻止提交，不删除边、不阻止继续编辑。
- `<Picture n>` 编辑辅助：检查器参考图列表逐行显示 `<Picture n>` 标记；手动提示词编辑器提供「插入参考图标记」下拉，可把 `<Picture 1>`…`<Picture n>` 插入光标处；提示行说明标记与上传顺序一一对应。系统不改写用户提示词，避免把普通文本误替换成参考图标记。
- 连线变化只更新画布草稿与即时校验，绝不自动创建计费任务；任务仍由卡片、浮动工具栏或属性面板的显式生成操作提交，提交时重新解析提示词与参考图，避免使用过期状态。
- 文字节点同样支持「以此生成」：自动创建生成节点并连一条文字边；图片节点「以此生成」在参考图数量兼容时自动连一条参考边。分支生成继承提示词和工作流，连线语义与普通连线一致。
- 持久化不新增字段，`schemaVersion` 保持 2，边数组是提示词来源与参考图顺序的唯一事实来源；后端接口、`jobs` 表与工作流注册表未改动。
- 纯逻辑集中在 `canvas-generation.ts`：`canvasPromptEligible`、`incomingGeneratorPromptNodes`、`resolveGeneratorPrompt`、`generatorPromptInfo`、`generatorPromptIssue`、`generatorReferenceIssue`、`validateGeneratorInput`；新增 4 项单测。

验收结果（隔离环境：Vite 5174 + SQLite 后端 7866，局域网地址 + 无头 Chrome/CDP，桌面 1440×900）：文字节点「以此生成」自动创建并连线，生成节点卡片显示「文字节点」标记与合并后的提示词；编辑文字内容后两个相连生成节点实时同步。切换为「LightX2V 多参考视频」后卡片、浮动工具栏与检查器立即显示「支持 1-9 张参考图，当前 0 张」并禁用提交，节点保持「待提交 / 尚未提交」，未创建任务；连入一张 `https://picsum.photos/...` 图片后警告消失、提交恢复，检查器显示「1 图片占位 连线顺序即提交顺序 · `<Picture 1>`」与编号映射提示；断开图片边回到 0 张警告，断开文字边回落到手动提示词，重连后恢复；浅色与暗色下卡片提示、来源标签、只读提示词和 `<Picture n>` 标记对比度正常，控制台无新增错误。未提交真实生成任务。

### 3.12 数据与接口现状

画布内容是一个 JSON 对象：

```json
{
  "schemaVersion": 2,
  "canvasSettings": {
    "viewport": { "x": 0, "y": 0, "zoom": 1 },
    "connectionMode": "full",
    "generationDisplayMode": "aggregate",
    "gridVisible": true,
    "minimapVisible": true,
    "guidesVisible": true,
    "globalPrompt": "电影感冷色调，雨夜霓虹",
    "viewpoints": [{ "x": 0, "y": 0, "zoom": 1 }, null, null]
  },
  "nodes": [
    {
      "id": "text_xxx",
      "type": "text",
      "position": { "x": 120, "y": 80 },
      "data": { "text": "开场：雨夜街道" },
      "style": { "width": 260 }
    }
  ],
  "edges": [
    {
      "id": "cc-edge__a|out|b|in",
      "source": "a",
      "target": "b",
      "sourceHandle": "out",
      "targetHandle": "in",
      "type": "smoothstep"
    }
  ]
}
```

节点类型与数据：

| 类型 | `data` 主要字段 | 说明 |
| --- | --- | --- |
| `text` | `text` | 文字节点，宽度固定默认 260 |
| `image` | `url`、`label`、`mediaKind`、`assetPath?`、`sourceJobId?`、`sourceRun?` | 图片节点；由生成结果插入时保留来源任务与提交快照 |
| `video` | `url`、`label`、`mediaKind`、`cover?`、`coverSource?`、`coverTime?`、`assetPath?`、`sourceJobId?`、`sourceRun?` | 视频节点；由生成结果插入时保留来源任务与提交快照。`cover` 为 320 px 长边、JPEG 0.66 的 data URL（≤64,000 字符），`coverSource` 记录取帧时的视频地址，`coverTime` 为取帧秒数；三者仅在同一地址下有效 |
| `artboard` | `label` | 画板节点，宽高存在节点 `style` 上，`zIndex: 0` |
| `generator` | `label`、`prompt`、`workflowId?`、`optionValues?`、`jobId?`、`jobStatus?`、`jobError?`、`resultUrl?`、`resultKind?`、`resultPath?`、`branchDirection?`、`resultHistory?`、`resultIndex?`、`lastRun?`、`runHistory?` | 生成节点；`prompt` 是手动提示词，仅在无文字节点连入时生效；任务状态、最近 12 个结果版本与当前版本随草稿保存，任务本体仍在 `jobs` 表；`lastRun` 是最近一次提交的参数快照，`runHistory` 按任务号保留最近 12 次快照 |
| `unknown` | 原节点全部字段、`originalType` | 前端未注册的类型；`originalType` 保存原始 `type`，保存时还原并从 `data` 移除 |

`canvasSettings` 字段：

| 字段 | 取值 | 说明 |
| --- | --- | --- |
| `viewport` | `{x,y,zoom}` 或缺失 | 相机位置，缩放 0.1–2；缺失时自动适配 |
| `connectionMode` | `off` / `compact` / `full` | 连线显示三档，默认 `full` |
| `generationDisplayMode` | `aggregate` / `independent` | 结果留在生成节点内或自动插入独立结果节点，默认 `aggregate` |
| `gridVisible` / `minimapVisible` / `guidesVisible` | boolean | 网格、小地图、对齐参考线开关，默认开启 |
| `globalPrompt` | string，最长 2000 | 新建生成节点与无提示词分支的初始提示词 |
| `viewpoints` | 长度 10 的 `{x,y,zoom}` 或 `null` 数组 | 数字键 1–9/0 保存的视角 |

以上设置与生成结果字段均为可选增量，`schemaVersion` 保持 2；旧前端忽略未知字段，后端仍按不透明 JSON 保存。

运行快照字段：

| 字段 | 取值 | 说明 |
| --- | --- | --- |
| `jobId` | string | 后端任务号，与 `jobs` 表主键一致 |
| `workflowId` / `workflowName` | string | 提交时的工作流标识与显示名 |
| `prompt` | string，最长 4000 | 提交时实际生效的提示词（含文字节点合并结果） |
| `optionValues` | 对象，最多 40 项 | 提交时实际发送的可见参数；字符串值最多 200 字 |
| `parameterSummary` | string[]，最多 6 条 | 面向用户的参数摘要，每条最多 120 字 |
| `referenceCount` | number，0–99 | 提交时实际参考图数量 |
| `mediaKind` | `image` / `video` | 结果媒体类型 |
| `submittedAt` | number | 提交时间（毫秒时间戳） |

快照只用于画布内回显与追溯，不替代任务记录：任务状态、产物地址和错误仍以 `GET /api/jobs/{id}` 返回为准；任务删除后快照仍保留，界面明确标记「任务已删除」。

提示词与参考图不新增持久化字段，完全由 `edges` 表达：指向生成节点的文字节点按边数组顺序合并为提示词，图片与生成结果节点按同一顺序作为参考图（序号 1..n 对应 `<Picture n>`）。边数组顺序是唯一事实来源，复制、撤销和刷新后语义保持一致；后端只按前端提交的 multipart 顺序接收参考图。

列表预览摘要（`canvas_projects.preview_json`，接口字段 `preview`）：

```json
{
  "x": -438,
  "y": -188,
  "width": 1820,
  "height": 960,
  "nodeCount": 7,
  "items": [
    { "type": "image", "x": 0, "y": 0, "width": 320, "height": 200, "url": "/api/media/2026/10/a.png" }
  ],
  "links": [[0, 1]]
}
```

- 保存草稿时由服务端从节点/边重新计算，不信任客户端提交；`preview` 只用于列表卡片，不参与编辑器读写，画布内容仍是唯一事实来源。
- `x/y/width/height` 是全部节点包围盒（画板计入）；`items` 按画布节点顺序做等距抽样，最多 120 项，超过时均匀跳过中间节点而不是只截取前 120 个；`links` 最多 80 条，端点按抽样后索引映射，越界即丢弃。
- 媒体地址只保留图片节点 `data.url` 与图片结果生成节点的 `data.resultUrl`，最多 12 个、单个 768 字符，只接受 `/` 开头的站内路径或 `http(s)`。
- 视频封面（V4.7）只读取视频节点 `data.cover`，且必须满足 `coverSource === data.url`、`data.url` 为安全地址、封面为 ≤64,000 字符的 `data:image/(jpeg|webp|png);base64,...`；最多 3 张，封面总预算 36 KB，超出预算的封面直接省略。
- 预览摘要序列化上限为 48 KB（为 MySQL `TEXT` 的 64 KB 留余量）。超限时先从头移除已加入的封面（从最后一项开始），再清空图片 URL，再清空连线，最后按 60/30/0 缩减节点形状，保证写入的 JSON 不超限。
- 列表缩略图对视频优先绘制 `cover`（裁剪填充）并叠加播放标记；旧画布或跨域取帧失败的视频仍只用类型色与播放标记。
- 旧画布或新建空画布的 `preview_json` 为 `NULL`，接口返回 `preview: null`，列表显示原占位图标；下次保存或恢复历史版本后自动生成。
- 预览不改变历史版本内容与校验和；恢复历史版本会经 `save_draft` 同步刷新预览。

服务端约束：

- 内容上限 8 MB；最多 3000 个节点、6000 条边。
- 每个画布只保留一份当前草稿，版本号单调递增。
- 历史版本每个画布保留最近 200 条；前端历史版本表默认读取最近 50 条。
- 校验和由服务端按内容计算；客户端传入的校验和不匹配会被拒绝。
- 画布按 `owner_user_id` 隔离，管理员也不能读取他人画布。
- 标签与收藏直接存于 `canvas_projects`：`tags_json`（JSON 数组，最多 8 个、单个 24 字符）、`is_favorite`；回收站使用 `deleted_at` 标记，列表默认只返回未删除画布。
- 回收站中的画布不可读取详情、保存草稿、读取或恢复版本，也不能再次移入回收站；恢复与彻底删除都按当前账号校验归属。
- `DELETE` 始终是永久删除，会一并删除草稿和全部历史版本；回收站只影响列表可见性与访问，不做自动清理。

### 3.22 V4.8（自定义视频封面）

- 检查器入口：视频节点的「封面帧」区域新增取帧时间 `InputNumber`（秒，`min=0`、`step=0.1`、`precision=2`，带 `封面取帧时间（秒）` 无障碍标签）与「按时间取帧」「上传封面」「自动取帧」三个操作；缩略图旁继续显示封面大小与当前取帧时间，自动封面显示「自动」提示，上传封面不显示时间。

- 本地上传：隐藏 `<input type="file">` 只接受图片文件且不超过 `CANVAS_COVER_FILE_MAX_BYTES`（16 MB）；读取为图片后在 canvas 中按 320/240/200 px 长边与高质量/兜底 JPEG 质量逐档压缩，直到得到不超过 64,000 字符的 data URL。成功后写入 `cover` 与当前视频地址 `coverSource`，并清空 `coverTime`（表示非取帧封面）。
- 自动恢复：清空封面后节点 effect 会重新走自动取帧；「自动取帧」按钮本身只清除封面和缓存，不直接写入时间，避免与节点自动取帧逻辑重复。修改视频地址或从作品库替换素材仍会清空三者并重新取帧。
- 撤销隔离：新增共享类型 `CanvasCoverPatch`，编辑器 `updateNodeCover` 统一标记 `coverOnlyChangeRef` 后写入节点数据；检查器的手动取帧、上传、清除与节点自动取帧都走这条路径，修复了此前手动改封面绕过仅封面变更判定、污染撤销栈的问题。仅封面变更仍会触发自动保存，但不写入撤销/重做历史；改标签、移动等其它变更正常进入历史。
- 兼容与边界：草稿仍为 `schemaVersion: 2`，只复用 `cover`/`coverSource`/`coverTime` 三个可选字段；节点展示与服务端预览继续要求 `coverSource === url`，封面长度与 `data:image/(jpeg|webp|png);base64,...` 格式校验不变。视频取帧依赖目标地址支持 CORS；显式时间跳转还依赖服务端支持 HTTP Range，缺少 Range 时浏览器只能取到开头帧（本地验收媒体服务已实现 Range）。
- 测试：`canvas-cover.test.ts` 增至 7 项，新增时间夹取（含 0 与超出时长）和上传文件校验（非图片、超 16 MB 拒绝）；`tsc -b`、全量前端测试与生产构建通过；不新增后端测试，后端画布 18 项与作品库 10 项继续通过。

验收结果：见 3.13 的 V4.8 隔离验收条目。

### 3.23 V4.9（上传封面裁切）

- 上传入口：检查器「上传封面」仍只接受图片且 ≤16 MB；校验通过后不再立即压缩，而是打开 Ant Design `Modal` 裁切弹窗。取消、关闭或重新选择文件都不写入节点；应用成功后才通过既有 `onUpdateCover` 写入 `cover`、当前视频地址 `coverSource` 与空 `coverTime`，因此只封面变更仍不进入撤销栈。
- 裁切模型：`canvasCoverAspectRatio(aspect, width, height)` 提供 `original`（跟随原图宽高比）、`16:9`、`9:16`、`1:1`；`canvasCoverCropRect` 先在原图上按目标比例做最大内接矩形，浮点误差导致宽高超出图片时先夹取，再按 1–4x 缩放缩小矩形，最后以归一化焦点 `{x,y}` 居中并夹取到图片边界。`canvasCoverCropFocus` 与 `moveCanvasCoverCropFocus` 负责源像素矩形、舞台尺寸、屏幕位移与归一化焦点之间的双向换算。
- 弹窗交互：预览舞台长边固定 360 px，图片绝对定位并按 `stage.width / crop.width` 缩放；支持鼠标/触控拖动（`setPointerCapture`）、方向键每次 8 px（Shift 24 px）、三分线参考和「重置取景」。切换比例会保留当前缩放与焦点，重置恢复 1x 与中心点；摘要实时显示「裁切 W × H px / 输出 W × H px JPEG」。图片读取失败显示错误 Alert，加载中禁用应用。
- 压缩入口：`canvasCoverFromFile(file, crop?)` 先解析裁切矩形；合法时用 9 参数 `drawImage(image, sx, sy, sw, sh, 0, 0, dw, dh)` 只绘制裁切区域，非法或未提供时回退整图。之后仍按 320/240/200 px 长边与逐档 JPEG 质量压缩，直到得到 ≤64,000 字符的 `data:image/jpeg`；失败返回 `null`，不会留下半成品封面。
- 交互细节：弹出后默认「原始」比例和 1x；连续 `pointermove` 与快速键盘事件都从 ref 读取当前比例、缩放和焦点再计算，避免 React 批处理下使用旧渲染闭包丢失位移；拖动/按键只改变取景，不触发撤销栈。
- 兼容与边界：纯前端增量，`schemaVersion` 仍为 2，只新增 `CanvasCoverCropModal.tsx` 与 `canvas.css` 的 `.canvas-cover-crop-*` 样式；裁切结果被压平为一张 data URL，应用后不能再次调整裁切，只能重新上传。裁切只影响上传封面，自动取帧与按时间取帧不受影响。
- 测试：`canvas-cover.test.ts` 增至 10 项，新增比例预设与原始比例回退、裁切矩形的内接/缩放/边界/非法输入、焦点与拖动换算的越界夹取。

验收结果：见 3.13 的 V4.9 隔离验收条目。

## 4. 已知限制与风险

| 问题 | 影响 | 处理计划 |
| --- | --- | --- |
| 序列化只保留已知顶层字段（`nodes`/`edges`/`schemaVersion`/`canvasSettings`） | 未来新增的其它顶层字段仍会在保存时丢失 | 新顶层字段必须在 `parseCanvasContent`/`serializeCanvasDraft` 中登记并补测试 |
| `unknown` 节点只能移动、复制、删除并保留原始数据，不能编辑业务字段 | 打开含未来节点类型的画布时可读但不可改 | 升级工作台注册对应类型后自动恢复编辑；V2.3 检查器不接管未知节点 |
| 检查器只服务单选节点，多选时不展示属性编辑 | 批量修改标签/字幕需要逐个打开 | 设计如此；批量属性编辑另行评估 |
| 「从作品库替换」锁定当前节点媒体类型 | 图片节点不能直接替换为视频（反之亦然） | 设计如此；需要换类型时插入新节点后删除旧节点 |
| 拖放只支持作品库单张卡片，不支持多选拖拽或从操作系统拖入文件 | 批量导入仍需逐张操作或走「添加图片」 | 设计如此；V4.1 若做批量导入再评估多选拖放与文件拖入 |
| 素材 Drawer 固定在右侧且无遮罩，占用约 560px 画布宽度 | 小尺寸桌面窗口的可视画布变窄 | 桌面优先；窄窗口可先关闭 Drawer 再整理节点 |

| 精简连线只保留选中节点/边及其上下游连通链 | 未选中的独立分支会被隐藏 | 关闭或切换「完全」即可查看全部；数据不删除 |
| 视角只保存相机位置，不保存选择、右侧面板标签或素材面板状态 | 跳转视角后需重新选择节点 | 保持视角语义简单；与撤销栈分离 |

| 作品库分页基于已加载任务快照的内存查询，单次最多读取账号最近 500 个任务 | 极端大量任务时更早的产物可能不在作品库结果中 | 任务列表本身已有上限；需要全量检索时应在存储层直接查询产物表 |
| 画布列表已支持搜索/排序/复制/标签/收藏/回收站与结构化缩略图，但缩略图只覆盖保存时的摘要 | 摘要最多 120 个节点、80 条连线、12 张图片，旧画布在下次保存前仍是占位图 | 摘要是结构示意，不代表完整内容；超大画布会抽样；PNG 导出已在 V4.5 完成 |
| 标签最多 8 个、单个最多 24 字符 | 复杂分类需要拆分或缩短标签 | 前后端一致校验；编辑弹窗与 422 错误都会提示限制 |
| 回收站没有自动清理与批量操作 | 长期不处理会占用存储，批量整理需逐个操作 | 提供逐项恢复与彻底删除；后续可评估保留期限与批量操作 |
| 复制画布只复制标题与草稿，不复制标签和收藏状态 | 副本需重新打标签、重新收藏 | 保持“复制内容”的语义；如需要完整克隆再扩展接口 |
| 回收站中的画布不出现在「加入画布」目标列表，也不能打开编辑器 | 需要先恢复才能继续编辑或插入素材 | 设计如此，避免对已删除画布产生新内容 |
| 画布内容上限 8 MB，内嵌 `data:image` 容易触顶 | 超过上限后无法保存新改动，导入同样会被拒绝 | 6 MB 预警、超限拒绝保存并提示改用素材地址；V4.1 导出按当前内容生成，导入在文件大小与 UTF-8 字节两层校验 8 MB |
| JSON 导入是整画替换，且只接受与当前 schema 兼容的结构 | 不能增量合并节点，也不能导入结构非法的第三方 JSON | 设计如此；替换前会确认并写入撤销栈，导入后仍可 `Ctrl/⌘+Z` 恢复 |
| 加入画布每次只处理单个生成产物，URL 参数处理失败时只提示不回滚目标画布 | 批量转移多个结果需重复操作；新建画布失败插入时会留下空画布 | 产物本体仍可在作品库查看；后续可评估批量加入与空画布清理 |
| PNG 导出是结构示意图，不是编辑器像素级截图 | 画板/节点使用导出调色板与简化细节，界面上的选中态、端口、浮动工具栏不会出现；视频优先绘制已截取封面并叠加播放标记，无封面时只画播放标记 | 设计如此，便于分享分镜结构；需要像素级截图时另行评估无头浏览器渲染 |
| 跨域图片没有 CORS 时导出显示占位卡 | 远端素材图可能不出现在 PNG 中，只保留图片节点外形与标签 | 加载时先同源 `/api/media/{path}`，失败再试原始地址；建议素材使用站内路径或支持 CORS 的地址 |
| 超大画布导出会自动降低倍率 | 单边超过 8192 px 或总量超过 24 MP 时，2x 可能实际输出 1.x 或更低，文字变小 | 弹窗显示实际倍率与原因；可缩小画布范围或只导出选中节点 |
| 导出范围限定为选中节点时，只保留两端都在范围内的连线 | 跨范围的连线不会出现在 PNG 中 | 设计如此；需要完整关系时选择整个画布 |
| 导出时生成节点使用当前选中的结果版本，多版本只保留一个 | 其他历史版本不会同时出现在 PNG 中 | 需要多版对比时分别切换版本导出，或使用独立结果节点 |
| 图片加载最多等待 10 秒 | 远端图片很慢时导出按钮会保持禁用，超时后以占位卡继续 | 超时后仍可导出；先检查素材地址是否可达 |
| 导出使用浏览器内存生成完整位图 | 24 MP 上限下仍可能占用较多内存，低配设备可能短暂卡顿 | 已限制单边、总量和倍率；超大画布建议只导出选中节点 |
| 视频封面依赖浏览器取帧且需要 CORS | 跨域视频未返回 `Access-Control-Allow-Origin` 时 canvas 被污染，无法生成封面；节点与列表退回类型色/播放标记 | 检查器提示「跨域视频需目标服务器允许 CORS」；建议使用站内 `/api/media` 或支持 CORS 的地址 |
| 指定时间取帧依赖 HTTP Range | 媒体服务不支持 Range 时浏览器无法跳转，`seekable` 只有开头，显式时间会实际落在 0 秒附近 | 部署端确保静态媒体支持 Range（本次验收的临时媒体服务已实现 206）；否则使用自动取帧或上传封面 |
| 上传封面裁切只支持固定比例与缩放取景 | 不提供自由画幅、旋转或输出分辨率选择；裁切在压缩前一次完成，应用后不能再调整，需重新上传 | 已支持原始/16:9/9:16/1:1 与 1–4x 取景，结果统一压缩为 320 px JPEG；透明 PNG 仍转为无透明 JPEG。重新上传即可重裁，后续可评估独立封面编辑器/对象存储 |
| 手动修改封面不进入撤销栈 | 「按时间取帧/上传封面/自动取帧」误操作后不能用 `Ctrl+Z` 恢复上一张封面 | 与自动封面保持一致，避免取帧结果污染编辑历史；可重新取帧或上传覆盖；如需要封面撤销再单独设计 |
| 封面以 data URL 存入画布草稿 | 每个封面最多 64,000 字符，多个视频会明显增大草稿体积并计入 8 MB 上限 | 仅保存一张压缩封面；接近 6 MB 时按现有体积预警处理，超限需改用素材地址或移除封面 |
| 封面只对当前视频地址有效 | 修改视频地址会立即清空封面并触发重新取帧；旧封面不会误用 | 检查器修改地址时同步清空 `cover/coverSource/coverTime`；服务端预览也校验 `coverSource === url` |
| 列表缩略图只带最多 3 张封面且受 36 KB 预算限制 | 画布中视频较多时，靠后的视频只显示播放标记 | 封面是列表示意，不保证覆盖全部视频；编辑器内所有视频仍各自持有封面 |
| 缩略图摘要依赖保存动作 | 未保存的改动、旧画布或新建空画布仍显示占位/旧预览 | 自动保存完成后刷新列表即可更新；不引入独立的预览计算接口 |
| 视频预览的自动播放受浏览器策略限制 | 个别环境打开弹窗后不自动播放 | 用户可手动点播放；文档不承诺自动播放 |
| 多个文字节点的提示词按连线顺序直接拼接，任一已连接文字节点为空即阻断提交 | 空文字节点会让整条生成链无法提交 | 设计如此，避免漏词；节点卡片与检查器会指出需补充文字 |
| `<Picture n>` 标记只做插入辅助，不在画布上校验序号是否超出参考图数量 | 提示词可能包含不存在的 `<Picture 9>` | 提交前仍校验参考图数量；后续可在检查器标出越界标记 |
| 连线菜单只覆盖当前已支持的下游 | 视频节点、画板以及带未知/空工作流的生成节点没有候选，释放后不显示菜单 | 扩展新连线能力时同步更新 `canvas-connections.ts` 与测试；生成节点配置工作流后即可获得下游 |
| 上游任务失败或取消时占位结果节点保持「等待生成」 | 占位节点不会显示失败原因，只继续等待 | 重新生成成功后自动填入；失败原因仍在生成节点与任务详情中 |
| 占位结果节点在自动填入前会作为空媒体节点保存 | 单独打开该画布时无法看到上游尚未产出的内容 | 上游完成时自动填入；需要立即展示时仍可等完成后手动插入 |
| 从无结果生成节点预建的参考链暂不可提交 | 上游尚未产出图片时，下游生成节点的检查器会提示参考图没有可用地址 | 上游完成后自动恢复可提交；这是有意的依赖提示，不静默忽略 |
| 旧草稿的输出类型补齐会触发一次自动保存 | 打开含旧生成节点的画布时版本号可能增加一次 | 补齐只写入 `resultKind`，不改变节点、连线或生成参数；如不希望保存可在补齐前关闭页面 |
| 菜单创建的生成节点按参考图数量选择默认工作流 | 从图片创建生成节点时可能先落到视频首帧工作流，需要手动切换 | 保留节点内工作流选择；后续可按来源节点媒体类型细化默认工作流 |
| 每个生成任务只取首个产物展示和插入 | 多输出工作流的其余结果需到任务详情查看 | 作品库/任务页仍可查看全部；后续评估多结果卡 |
| 运行快照只在提交成功后写入，旧版本画布创建的结果没有快照 | 旧结果只能显示任务状态，无法回显提交时的提示词与参数 | 检查器显示「未保存提交时的参数快照」；需要追溯时到任务详情查看 |
| 快照对提示词（4000 字）、参数项数（40）、字符串长度（200）、摘要条数（6）和运行历史（12 条）做截断 | 超长提示词或大量参数在画布内只能看到截断值 | 完整值仍在任务记录与任务详情中；画布只保存用于追溯的摘要 |
| 来源任务状态只在检查器挂载、任务号/生成状态变化或手动刷新时核对 | 任务在任务页被删除或产物过期后，已打开的画布不会实时收到通知 | 点击「刷新状态」或重新选中节点即可更新；生成节点运行中仍按 2.5 秒轮询 |
| 从作品库直接插入的图片/视频没有 `sourceJobId` | 这类素材节点不显示来源任务与运行参数 | 只有生成结果才有任务回链；作品库来源仍可在素材路径中查看 |
| 画布生成不单独提供反向提示词与图片尺寸输入 | 需要这些能力时只能使用工作流 `options` 中已开放的参数 | 画布只暴露 schema 的 `primary`/`advanced`；后续按工作流产品化需要再开放 |
| 轮询请求失败被静默忽略，等下一次 2.5 秒重试 | 后端持续不可用时任务状态会停留在运行中，不显示刷新错误 | 避免打断生成；后续可在检查器提示「状态刷新失败」 |
| 切换工作流会清空当前任务号与结果 | 想保留旧结果需先「插入为图片/视频节点」 | 设计如此，避免跨工作流误读旧结果 |
| 没有多人协作/分享 | 只能单账号使用 | V5，需先做 Yjs spike 和权限设计 |
| 中文路径下后端单测可能报 `No module named 'backend'` | 属于启动器 `sys.path` 问题，不是业务回归 | 使用第 8.2 节的显式 `sys.path` 命令 |

## 6. V3 计划：生成节点与任务联动（V3.0–V3.3 已完成）

目标：让画布从「摆放素材」升级为「在画布内发起生成」。这是画布与现有任务系统的第一次深度接线，必须先做技术 spike，再写完整 UI。

### V3.0 技术 spike（已完成 2026-10-22，不改 UI）

- [x] 确认 `GET /api/modes` 中可用于画布的图片/视频工作流，只使用 `primary`/`advanced` 参数，`internal` 参数由后端默认值托管。
- [x] 验证从画布素材准备参考图：优先用同源 `/api/media/{path}` 或 `GET /api/jobs/{job_id}/outputs/{index}/download` 取字节，构造 `File` 后提交 `POST /api/jobs` 的 multipart `references`。
- [x] 如果云端 URL 存在 CORS/鉴权问题，评估一个窄接口：按素材 ID/path 在服务端复制到任务暂存区；不要开放任意 URL 抓取。
- [x] 验证 `POST /api/jobs` 的 CSRF 头、`options` 字符串、参考图顺序与现有前端生成页一致。
- [x] 记录 spike 结论到本文件，再决定 V3.1 的实现方式。

spike 结论：

- `GET /api/modes` 返回的 `parameters` 中 `name: "options"` 的 `schema.properties` 已包含 `ui_group`、`default`、`enum`/`ui_options`、`minimum`/`maximum`/`step`、`ui_visible_when` 和中文 `label`/`description`，画布无需新增“可生成工作流”接口；只展示 `primary`/`advanced`，`internal` 不渲染也不提交，由后端默认值托管。
- 参考图字节优先走同源 `/api/media/{path}`（图片节点 `assetPath`），也可用节点已有的站内路径或 `data:image/`；用 `fetch(..., { credentials: "include" })` + `fileFromReferenceBlob` 构造 `File`。没有新增“服务端按任意 URL 抓取”的接口：跨域 `http(s)` 地址取字节失败时提示用户从作品库重新插入，避免 SSRF 面。
- `POST /api/jobs` 继续复用生成页契约：multipart 字段 `mode`、`prompt`、`options`（JSON 字符串）、有序 `references`、`title`，写操作带 `X-CSRF-Token`；参考图以连边数组顺序去重后 append，与 R2V 的 `<Picture n>` 顺序一致。
- 结论：V3.1 直接在前端复用现有契约，不新增后端接口、数据表或第二套任务队列。

### 8.3 桌面浏览器验收

默认只验收桌面端，浅色和暗色都要看：

1. `/canvas`：空态、新建、列表信息、重命名、标签编辑与筛选、收藏置顶、全部/收藏/回收站视图、移入回收站、恢复与彻底删除确认。
2. 编辑器：添加四类节点、拖动、连线、缩放/平移、MiniMap、双击预览。
3. 编辑链路：输入文字、撤销/重做、复制、删除、从作品库插入、视频播放。
4. 多选与整理：`Ctrl/⌘ + 点击` 选中三个节点，执行顶部对齐后位置一致，`Ctrl/⌘ Z` 恢复原坐标；多选复制产生内部连线、多选删除不残留关联边；单选一条边可单独删除并撤销；打开「快捷键说明」Popover 核对键位。
5. 保存链路：等待自动保存、刷新恢复、历史版本恢复、模拟 409（两个窗口同时编辑）；断网后确认状态为「重试中」并在恢复网络后自动保存；接近 8 MB 显示预警，超过 8 MB 显示错误且不进入重试。
6. 视口与大画布：平移缩放后刷新，视口保持；300 节点以上的画布缩放后仍能选择、打开检查器、拖动并自动保存。
7. 生成节点：添加生成节点，选择图片/视频工作流并填写提示词；连接文字节点作为提示词（编辑文字节点应实时同步，空文本应阻断提交），连接 1–2 张图片节点作为参考图，在检查器核对序号、`<Picture n>` 标记与数量；切换工作流后确认不足/超限提示立即出现且提交按钮禁用，连线变化本身不创建任务；提交后观察排队/生成/进度/完成或失败，运行中可停止；成功后预览、插入为图片/视频节点，并通过「在任务详情中打开」核对同一任务；刷新后任务号与终止状态仍在。任务只在显式点击提交后创建。
8. 主题：浅色 `#f8f9fa` 画布基线、暗色 `#0f1115` 画布基线，弹层（Modal/Drawer/Tooltip/Select/Popover）也必须跟随主题。
9. 键盘：`Ctrl/Cmd+Z`、`Ctrl/Cmd+Shift+Z`、`Ctrl/Cmd+Y`、`Ctrl/Cmd+D`；`Ctrl/⌘ + 点击` 多选、`Shift + 拖拽` 框选；在输入框中不应触发画布撤销。
10. PNG 导出：编辑器「更多 → 导出 PNG」打开弹窗，核对默认范围、背景与倍率跟随当前主题；切换整个画布/选中节点、浅色/深色/透明与 1x/2x 时预览和「输出像素」同步变化；超出 8192 px 或 2400 万像素时提示自动降采样；点击导出下载 `${标题}-YYYYMMDD-HHmm.png`，浅色四角为 `#f8f9fa`、深色为 `#0f1115`、透明图带 alpha；隐藏节点/连线与选区外部连线不出现在结果中；视频节点有封面时图片区域显示封面帧；关闭弹窗与导出成功后控制台无报错。
11. 作品库分页与检索：打开素材 Drawer，核对图片/视频标签显示服务端计数且首屏 40 项；输入关键词后请求带 `q` 并防抖，清空恢复；滚动或点击「加载更多」加载后续页且无重复卡片；搜索无结果时显示空状态；从生成历史「加入画布」跳转一个不在首屏的旧素材，确认能精确插入且 URL 参数被清理；控制台无报错。
12. 视频封面帧：添加一个使用站内或支持 CORS 的视频节点，等待加载后确认节点显示首帧、检查器「封面帧」出现缩略图与大小；输入一个合法时间（例如 1.5 秒）点「按时间取帧」，确认摘要显示实际取帧时间；输入超过时长的值点取帧，确认被夹取到结尾；点「上传封面」选择一张 PNG/JPG，确认先打开「裁切封面」弹窗。依次切换原始/16:9/9:16/1:1，检查裁切与输出尺寸；拖动图片或用方向键取景，并调整缩放确认画面与尺寸同步；点「应用裁切」后确认摘要不显示时间、缩略图按裁切结果更新且实际像素不超过 320 px。点「取消」或关闭后重新打开，确认回到原始比例与 1x 且现有封面不变；选择非图片或超过 16 MB 的文件应提示并保持弹窗关闭。点「自动取帧」恢复开头帧；以上操作后撤销按钮均不应因此启用。点击「重新截取」后封面重新生成；修改视频地址后旧封面清空并重新取帧；保存后返回列表确认卡片显示当前封面；打开预览确认 poster 生效；用不支持 CORS 的跨域视频确认退化为占位且不报错。
13. 连线拖拽菜单与流光连线：从文字节点右侧端口拖出一段距离后松开，确认拖拽过程为虚线、松开后出现「添加节点」菜单且只有「生成节点 / 以这段文字作为提示词」；选择后新节点自动出现在空位并用实线连接，连线带持续流动的光点。从图片节点拖出，菜单应有「生成节点 / 以这张图片作为参考图」。从尚未生成结果的图片生成节点拖出，菜单应出现可直接选择的「生成节点」与「图片节点」；选择图片节点后创建一个标题为「等待生成」的占位节点并连线，卡片内提示「等待上游生成完成，自动填入」。从尚未生成结果的视频生成节点拖出，「视频节点」同样应可直接选择。已有结果的生成节点直接带入结果。上游任务完成后确认占位节点自动显示结果；上游失败或取消时占位节点保持等待状态，重新生成成功后填入。从视频源、画板和未知工作流的生成节点拖出不应出现菜单。选择菜单外区域、按 `Escape`、平移画布或切换工具应关闭菜单与残留虚线；在菜单中创建节点后可 `Ctrl/⌘+Z` 一并撤销节点与连线。旧草稿中的文生视频节点加载后输出端口应为视频色；浅暗主题下待选虚线、菜单与流光都清晰可见，`prefers-reduced-motion` 下流光停止但连线保持实线。
14. 连线与生成模式快捷弹层：点击底栏「连线与生成模式」图标，确认弹层含「连线（关闭/精简/完全）」与「生成节点展示方式（独立/聚合）」两组、每项有说明和选中对勾，默认完全/聚合。切到精简后不选中任何节点时连线应为 0 条；悬停一个有连线的节点时只显示其上下游连通链，移出后恢复 0 条；选中节点或最近创建的边同样保留其连通链。切到关闭时连线为 0 条且节点端口不可见、不能拖出新连线；切回完全恢复全部连线。属性面板的标签、顺序和说明应与弹层一致。浅暗主题下弹层文字、选中态、图标对比清晰；刷新后所选模式保持。
