## 3. 目标写稿链路

```text
已采纳扩写剧本 + 当前组原镜头 + 前后镜必要上下文 + 有序参考及使用范围
                         ↓
明确选择的 GPT-6 写稿配置 + 完整指定 skill + 最小接入合同
                         ↓
一次生成整组完整稿：主体/场景定义、声音设定、连续镜头正文
                         ↓
确定性结构检查 → 内容审查 → 必要时有限返修
                         ↓
现有预览：公共设定差异 + 全组镜头候选
                         ↓
原子采纳：公共设定归组、正文归镜头、调用证据归任务
                         ↓
确定性编译及文本一致性检查 → 当前远端 ComfyUI → 真实音画验收
```

### 3.1 作者模型必须可追溯

- 在现有供应商体系内增加 Director 写稿用途的明确模型选择，复用凭据管理，不读取或复制 Codex 私有登录凭据。
- 用户要求的 GPT-6 必须由实际配置的 API 提供；具体模型 ID 以供应商可用能力为准，不假定桌面模型名可直接用作 API 模型名。
- 若模型支持图片，由同一作者直接看图写稿。若不支持，不能静默换成 VLM 写稿：应明确报告能力缺口；可另行启用“VLM 提取外观事实、指定作者写稿”的显式模式，并标注其不属于原样复现。
- 记录 requested/actual model、供应商标识、推理设置、温度、请求 ID（若可得）、是否回退、耗时及 token 用量（若可得）。不保存密钥。
- 模型不可用时保留候选与错误，不能悄悄换模型后显示“满意版生成成功”。

### 3.2 skill 与输入合同

- 唯一创作 skill：`skills/MINIMAXH3格式动作语气台词细化SKILL/SKILL.md`，完整加载。
- 最小接入合同只明确：原剧情与对白、已确认镜头范围/时长、参考图映射、无参考音频这一事实、用户显式锁定项、交付边界。
- 餐厅、人物、音频编号、白名单和禁项是示例，必须按本剧本适配；不能把禁止碰触无关物件写成禁止翻书拿笔。
- 用户锁定的参考顺序、人物身份、对白和明确声音偏好不可改；系统自动补出的泛化公共设定允许作者改善。历史记录没有来源标记时，在候选里展示差异，采纳前不得覆盖。
- 整集剧本保持来源可追溯。超出上下文预算时明确提示并使用有记录的上下文裁剪方案，不静默截断。
- 只要求一次完整组稿，不另开导演设计、多层扩写或默认多代理流程。

### 3.3 完整创作与 v7 存储解耦

- 推荐作者输出 skill 的完整文本，再用确定性解析器拆出公共设定和各镜正文；不用另一个 LLM 对正文进行二次包装。
- 原始完整稿与解析结果一起保存在任务候选中。解析器只处理明确边界和编号，不重写动作、对白、音效或约束。
- 解析失败只做格式修复；保留原稿及差异。禁止因解析失败回退到旧六段式。
- 全组候选包含公共设定与镜头正文。通过现有采纳操作在同一事务提交，检查方案 revision、剧本和参考指纹；不得发生公共设定已更新而正文仍旧的混合状态。
- 单镜返修传入完整组稿上下文，冻结公共设定及其他镜头。若问题必须修改共享声音/场景，则返回“需整组返修”及理由，不越权修改邻镜。
- 指纹纳入正文、公共设定、来源、参考与写稿合同版本；历史版本可读，不批量重算并覆盖用户作品。

## 4. 检查与返修设计

### 4.1 硬性结构检查

- 原镜头完整、顺序正确；原对白逐句一次且说话人正确。
- `<d>[中文]…</d>` 完整；Subject、Picture 与声音映射一致，无虚构参考音频。
- 时间有效并在本镜范围内；累计/局部时间与执行帧段一致，不能重复偏移。
- 最后对白后有明确闭口或静默收束，至少保留当前约定的 0.5 秒。
- 关键动作分段覆盖开场、动作转换、对白与收束；无对白镜头同样检查。允许同一时间窗内明确并行动作，不机械禁止自然声画重叠。
- 逐段精度表示模型指导粒度，不宣称视频能严格逐 0.1 秒执行。

### 4.2 内容审查

- 检查拿笔/写字/翻页/说话的顺序、手部占用和物件位置是否矛盾。
- 检查先接收刺激再反应、上一镜落幅与下一镜开场是否衔接。
- 检查对白语气和音量是否符合人物任务；人声可辨、无额外台词、无旁白（剧本要求旁白时除外）、环境声不遮盖对白。
- 检查约束是否与剧情冲突、是否照搬 skill 示例、是否只有“选了继续……”等抽象结尾而无具体姿态。
- 字速统一按共享策略给风险提示；低声不自动代表慢速。时长无法容纳时报告冲突，提出调整候选，不擅改对白或镜头时长。
- 语义问题给出原文证据、影响镜头与局部修订建议，不把模型审查当客观音频验收。

### 4.3 有限返修

- 默认首次生成 + 最多两次返修，总计三次调用；无进展、违反锁定项或达到上限时停止。
- 每次保留输入、原稿、问题与差异；只修报告中的问题。后稿退步时保留较好版本，但仍明确未通过，不伪装成功。
- 不默认以重试直到过关代替质量恢复，也不自动调用视频生成来盲试。

## 6. 对照实验：区分作者、程序与视频生成

1. **编译保真对照（先不生成视频）**：满意稿输入新解析/编译链，逐字段核对最终公共文本、镜头正文、参考顺序、起始帧和帧数。只允许有记录的容器与时间表示转换，不允许改写内容。历史稿不符合新增字速建议时，保留原文并记录提示，不能偷偷改稿后称原样复现。
2. **作者对照**：固定同一份 skill、剧本、镜头范围、参考和最小合同，比较指定 GPT-6 与旧作者链路；另固定同一作者比较旧/新合同。先评审文本，不把模型差异与合同差异混在一起。
3. **两镜视频对照**：优先在原始参考和参数可找回时复现满意两镜；否则使用双方一致且已记录的参考与参数，明确为受控新对照。满意文本与新生成文本使用相同 H3 工作流、模型权重配置、尺寸、fps、帧数、音频模式和 seed。
4. **三镜产品验收**：回到当前组 1 的三镜及已确认四张参考，检验第二镜最后一句和第三镜无对白要求；与两镜实验分开报告。
5. 首轮每个对照条件一次生成；若结果不稳定，再用相同的第二个 seed 配对复测。固定 seed 不保证远端推理完全确定，记录该限制。每轮先分析证据，再决定是否追加。
6. 真实视频前读取当前 `comfy_provider_settings.base_url`，经 `provider_bridge.comfy_row()` / `ComfyProviderService.current_url()` 获取实际远端地址，确认队列和能力。不切地址，不测试默认本机 8188，不部署第二套实例，不擅改节点 ID 或模型路径。
7. 所有实验作为候选/测试任务留存，不自动采用或覆盖当前媒体。第一组通过后才推广；不批量重生成整集。

若相同满意文本通过程序和原路径的最终请求一致却仍有对白异常，应继续查远端模型/节点/音频生成配置与随机性；此时不能继续把原因笼统归于写词。

## 7. 最终验收标准

### 提示词验收

- 完整场景与声音设定、逐段具体动作、对白归属、镜间衔接均达到满意稿的具体程度。
- 不照搬餐厅示例，不存在手部/物件冲突，不用泛化禁项压住剧情。
- 不为通过字速检查破坏表演节奏；无法兼顾时长时明确暴露冲突。
- 真实作者与最终送片文本可查，结构通过、内容审查通过、成片验收通过是三种不同状态。

### 成片验收（必须实际观看及听辨）

- 两句对白与原文一致，尤其“再查查出处，应该还有线索。”完整、清晰、可辨为中文，无遗漏、重复、额外词句、伪语言或尾音截断。
- 同一人物声音稳定，口型与对白无明显错位，背景声不掩盖台词；第三镜无新增人声。
- 拿笔、写字、翻页与说话顺序合理，镜间人物、道具、姿态及光线没有明显跳变。
- 可用 ASR 对照原文辅助发现遗漏，但 ASR 正确不等于人耳效果合格；自动化不能代替实际音画检查。无法听辨时标明未验收。
- 最终由用户确认达到认可版本的效果；在此之前只报告已完成的技术和音画检查，不宣布“恢复成功”。
