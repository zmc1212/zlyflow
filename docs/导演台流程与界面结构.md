## 2. 导演台2 首页（DirectorHome，原导演台首页）

- **顶栏**：左「导演台」，右主题切换（ThemeToggle）；移动端另有返回创作工作台、新建按钮。
- **Hero 区**：大标题「今天，想拍点什么？」，副题「用 AI 将你的创意变成精彩的影视作品。」
- **四个创作入口**（横向卡片，主卡 `grid-row: 1 / 4` 对齐右侧三张小卡）：
  1. **导演创作**（主卡，浅蓝渐变，右侧拍立得装饰插画）：「一句话开始，完成剧本与分镜」；步骤指示 `1 故事 → 2 角色 → 3 分镜`；CTA「+ 新建导演工程」。
  2. **短视频批量**：「一个主题，生成多条短视频」，右箭头。
  3. **参考片复刻**：「分析参考片，批量转绘」，右箭头。
  4. **Hypit 复刻**（2026-09-19）：「拆结构、换内容、合字幕图形」，右箭头；不得写成锁运镜转绘。浅色卡底 `--dh-hypit-bg: #fff4e5`，暗色 `#2a2218`。
- **最近工程**：卡片网格（默认显示 6 个，超出出现「查看全部/收起」）。每卡：有 `script.coverUrl` 时显示用户上传的剧本封面，无封面时显示类型图标封面（导演创作=蓝/批量=紫/VACE 复刻=绿/Hypit 复刻=橙 `--dh-cover-d`）、标题、梗概（无则「暂无梗概」）、类型 chip（导演创作/短视频批量/参考片复刻/Hypit 复刻）+ 状态 chip（待生成/部分完成/已完成；Hypit 有成片 URL 为已完成，有参考片或转写为部分完成）、元信息（`N 个镜头`、更新时间），操作「打开 / 复制 / 删除（Popconfirm：工程文档会从服务器移除，已生成的视频任务仍保留在任务列表）」。
- 空态：「还没有导演工程」+「从上方选择一种创作方式，开始你的第一部片。」+ CTA「新建导演工程」。
- 2026-09-16 起：该页归属侧边栏「导演台2」入口，顶栏与移动端标题改为「导演台2」；同款首页已复刻到 `/director2`（导演台），见文末「导演台入口互换与导演台（/director2）新首页」章节。

## 3. 导演创作（Recipe）：九阶段流程

核心页面 `DirectorRecipeStudio.tsx`。左侧阶段导航（`DirectorStageNav`）分 4 组 9 阶段（2026-09-13 起视觉素材组新增「道具定妆」子阶段，`props` 提升为与角色/场景并列的真实导航阶段，后端九环节 agent 流水线不变、道具仍由 characters 环节产出；同日「分镜设计」阶段并入「镜头设计」，旧链接 `?stage=storyboard` / `board` 重定向到 `shots`），每阶段带就绪标签：

| 分组 | 阶段（id） | 就绪标签 |
| --- | --- | --- |
| 故事与风格 | 剧本 `script`、画风 `art_style` | 未开始 / 草稿 / 部分完成 / 已就绪 |
| 视觉素材 | 角色定妆 `characters`、场景定妆 `locations`、道具定妆 `props` | 同上 |
| 镜头设计 | 镜头设计 `shots` | 同上 |
| 声音与交付 | 配音 `voice`、配乐 `music`、成片 `export` | 同上 |

组标题右侧显示 `已准备/总数` 计数（视觉素材组 = 角色 + 场景 + 道具的已采纳资产数 / 资产总数）；阶段名左侧圆点表示就绪级别，右侧 Tag 显示标签文字。URL 参数 `?stage=<id>` 直达阶段（含 `?stage=props`），`?view=timeline` 进入剪辑视图，`?mode=manual` 进入手动编辑模式。

### 3.0 创作模式（AI 生成 / 手动编辑）

顶栏右侧常驻 antd Segmented「创作模式」切换（`DirectorCreationModeSwitch`，魔杖图标「AI 生成」/ 铅笔图标「手动编辑」），所有阶段（含剧本对话页、剪辑视图）可见；移动端收进顶部栏为紧凑图标形态。模式真源为 URL `?mode=manual`（可分享），缺省读工程级 localStorage 记忆（`director-creation-mode:<projectId>`），再缺省「AI 生成」；切换即写入 URL + localStorage，切阶段、刷新均保持，并以 antd message 即时反馈（「已切换到手动编辑，可直接编写各环节内容」/「已切换到 AI 生成，可继续用 AI 打磨各环节」）——画风等阶段两种模式界面几乎一致，没有该提示用户会误以为切换无效。流水线生成进行中切换被禁用，避免遮挡流式进度与取消入口；澄清问题待答**不再锁定**模式切换（2026-09-14 修订，原「流水线或澄清应答均禁用」会导致未回答的残留问题卡在所有环节永久禁用开关且无提示）：未答问题卡继续保留在剧本对话室（localStorage `director-clarify:<projectId>`），切回 AI 生成后仍可作答或跳过，新一轮生成会自动丢弃旧卡。

- **AI 生成（默认）**：既有九阶段 agent 流程与对话创作室，行为不变。
- **手动编辑**：直接编写与修改各环节内容，跳过 AI 写作：
  - 剧本：**与其他阶段同布局**——左侧阶段导航与任务头（「剧本 · N/N 项已准备」+ 就绪 Tag + 导航主按钮）正常显示，可随时点击导航跳到分镜、角色、配乐等环节手动编辑（AI 生成模式的剧本阶段仍隐藏导航，保持全屏对话式）；主区渲染专属手动工作区（标题「手动编辑剧本」+ 说明「直接修改片名、梗概与完整故事，改动会自动保存；左侧阶段导航可随时切换到分镜、角色、配乐等环节手动编辑。切回『AI 生成』可继续用 AI 打磨或重跑后续环节。」），`DirectorScriptDocument` 默认展开为编辑表单（片名/一句话梗概/完整故事 + 封面上传），内容为 860px 居中栏；「完成编辑」切只读成稿，可再点「编辑剧本」。空工程可从零手写。Prompt Bar、澄清卡、继续生成与 AI 记录流全部隐藏，切回 AI 生成即恢复。
  - 画风：目录选卡本就是手动操作，无变化；手动模式下不再显示「生成创作方案」主按钮。
  - 镜头设计（设计模式）：隐藏「根据剧本生成分镜」AI 拆解入口与「按剧本重新生成分镜」菜单项；空态 CTA 为「新建空白镜头 / 导入手动分镜（粘贴 Markdown）」，有镜头时 bin 工具条提供「新增镜头」。
  - 角色 / 场景 / 道具：工具条新增「新增角色 / 新增场景 / 新增道具」按钮（两种模式都有），新增空实体后走与 AI 生成卡片相同的编辑表单与自动保存；空态文案改为「手动新增、AI 生成或从资产库插入人物、道具 / 场景」。
  - 配音 / 镜头设计（制作模式）/ 成片：执行类操作（定妆、静帧、渲染、TTS、合成）全部保留。
  - 手动填写的内容即时进入就绪度模型（就绪度纯由 payload 派生）；切回 AI 生成时引导链自动跳过已有内容的环节。
  - 「任务活动」抽屉在手动模式下隐藏各环节「生成/重跑」按钮（AI 写作入口）。
  - 移动端底部主操作条同步过滤：手动模式下分镜空工程无 AI 主按钮，仅保留导航类按钮。

### 3.1 剧本阶段 —— 对话创作室（chat room）

布局：`director-script-room`，无阶段导航（全宽对话式），底部停靠 Prompt Bar。

- **空态 hero**：魔杖图标 +「从一句创意开始」+ 说明「在下方输入你的故事创意，点击发送，AI 导演会先和你确认创作方向，再逐步写出片名、梗概和完整故事。」+ 3 个可点击示例创意 chip（程序猿与 AI 编程 / 镖师忠义与爱情 / 外卖骑手暴雨夜订单）。空态同时提供「剧本封面图 · 可选」上传入口；未上传时不展示叙事背景图。
- **Prompt Bar**（`DirectorPromptBar`，复刻 beautifului Prompt Bar 模式）：圆角 22px 白色胶囊输入条，placeholder「例如：雨夜里侦探穿过霓虹暗巷，追上一个撑红伞的女人。」，右上圆形发送按钮（↑，armed 时主色）；hint「Enter 发送，Shift+Enter 换行；生成方案只整理创意，不会自动消耗定妆、视频或配音额度。」
- **澄清问题卡**（`DirectorClarificationCard`，由 `DirectorScriptStreamPanel` 与导演台2共用）：标题「AI 导演正在规划你的创意」，hint「回答或跳过下面的问题，剧本会按你选择的方向写。」，进度「创作方向 N/M」；每题逐行展示后端返回的全部预置选项（含推荐项），并额外保留「输入你的想法」可输入项，至少四行，不能压缩成三选项；预置项更多时继续保留对应行。预置选项单击后立即高亮，480ms 后自动进入下一题；输入自定义答案时清除预置项选择，二者不共用值。操作「跳过这题 / 跳过全部，直接生成 / 按这个方向开拍」。逐环节确认（画风/角色/场景/分镜/配音/配乐）各有对应标题与 hint（`STAGE_CLARIFY_TITLES/HINTS`），回答后按环节定向注入。
- **流式写作**：状态头「AI 导演正在创作」+ 脉冲圆点动画（`director-stream-pulse-ring`）；分段标签「正在写：片名 / 一句话梗概 / 完整故事」；用户创意以「你的创意」气泡置顶；「回到底部」悬浮；生成任务行（`生成任务`，胶囊行 + 环形进度 + 成功/失败徽标 + 重试）。
- **共享直播卡与取消状态（2026-09-15）**：`DirectorLiveStepFeed` 提供记录流的完成步骤行与当前展开直播块，导演台和导演台2共用同一 DOM 类名、状态图标、hover chevron、摘要 chip、spinner、圆角、阴影、间距与动画；导演台2的五阶段流消费同源 `status / agent / agent_delta / agent_item / done / cancelled / error` 事件。点击「取消生成」后按钮立即 loading/disabled，头部与当前卡显示“正在停止当前生成”，事件流和状态轮询保持到后端发送 `cancelled`，已完成步骤不清空。

## 2026-09-16 导演台2 AI 逐步卡点确认

### 流程

导演台2 AI 创作室（`/director2/projects/:id`，`Director2AiStudioPane`）在创意确认（集数 + 每集默认镜头数）之后按四个真实卡点推进，不再一次性跑完整条流水：

1. **剧本** `script`
2. **角色 / 场景 / 道具** `assets`
3. **分集** `episodes`
4. **分镜** `storyboard`

每步跑完进入 `awaiting_review`（暂停、无 worker）。用户可「采纳」进入下一步，或「不满意」用对话反馈只重跑当前步。已完成的更早阶段可单独「重新生成」：该阶段之后不再算完成，确认后需再次生成；底部「从当前阶段重试」仍只续跑停住的那一步。创意确认重开时在同一条 pipeline 上重新出开场问题，答完从剧本重跑。最后一步采纳后任务 `succeeded`。同一项目同时只允许一个占用中的 AI 任务（含待确认 `awaiting_review` 与调整中 `revising`）；刷新后由 `GET …/ai/operations/active` 接管。进程重启不会把待确认任务标失败。

### 界面结构

- **页头**：待确认显示「第 N 步已生成，请确认」（剧本=1 … 分镜=4）；调整中显示「正在按你的反馈重新规划…」。副文案用该阶段直播/确认消息（如「剧本已生成，请确认或提出调整」）。
- **左侧任务栏**（`DirectorTaskRows`）：`awaiting_stage` 之前的步骤为已完成，当前步胶囊「待确认」，后续为未开始。状态胶囊（已完成 / 失败 / 待确认）全部右对齐：行尾固定预留重生成按钮槽位，按钮绝对定位，不把「已完成」挤离右缘。已完成行 hover 出「重新生成」；失败行仍是「失败」pill 重试当前步。窄栏只做进度，不塞问答。
- **创作路径 Tool Chips**（记录流、用户创意气泡下方）：`DirectorPathChips` 复用 `.director-direction-chips.is-path`。标题单独一行，其下按阶段分行（阶段名固定列宽，选项 chip 跟在右侧）。开机确认题按题意挂到真正受影响的步骤（结局/基调→剧本，主角/角色→角色·场景·道具，集数→分集，镜头数→分镜），chip 文案写选项 **label**（如「1 集 · 单集成片」）而不是 Agent 用的 value「1」。`title` 为完整 `问题 → 答案`。跳过未作答的题；直接「采纳」且没有可继承选项的阶段不出现在路径条，也不再显示「已采纳本次生成」。390 宽阶段名与 chip 上下堆叠。对照 beautifului Tool Chips 的紧凑胶囊，不新装库。
- **记录流确认卡**（`DirectorLiveStepFeed` 的 `director-block` / `director-completion-card`，复用导演台视觉）：展示该步直播/产出内容。文案「这一步可以进入下一步吗？」；最后一步为「分镜已经生成，确认后完成本次创作」。按钮「不满意，调整」+「采纳，继续下一步」（最后一步「采纳，完成创作」）。
- **完成步骤行选项回显**（`DirectorLiveStepRow` 卡片行下只读问答列表，非手风琴、非换行 chip）：询问卡提交后立刻变成收起态。每条为「问题（弱化）| 答案（主文案）」两列；创意确认行展示全部开机选项；剧本 / 角色 / 分集 / 分镜行展示该步继承到的开机选项，以及该步「不满意」后再答的选项（后者覆盖同题）。整张卡「跳过全部」且无答案显示「已跳过，沿用默认」；直接「采纳」不再用假选项「已采纳本次生成」占位。创意确认完成行摘要优先用集数题 label。点步骤行打开抽屉时，抽屉顶部同样列出该步选项，下面才是产出。提交询问卡时写入 `label`，并在 pipeline `request.clarify_questions` 保留题面以便刷新后把 value 还原成 label。
- **记录流排版**：页头标题 16px、说明最多两行；用户创意为右对齐软色块；步骤行是 inset 卡片，阶段名 14px，右侧摘要不再拉满成矮 chip 条。
- **Prompt Bar**：待确认且未点调整时占位「点「不满意，调整」后，在这里说明想怎么改…」；点调整后切成「说明想怎么改…」，提交调用 `revise`。`awaiting_review` 不锁 Prompt Bar；`revising` 视为进行中并订阅 SSE。
- **阶段澄清卡**：出题后复用 `DirectorClarificationCard`（选项自动翻页、自定义输入、跳过本题/全部）。作答调用 `rerun` 只重跑当前步，完成后回到同一阶段确认卡。创意确认重开时同一张卡答完从剧本重跑。
- **记录流步骤行**：已完成步骤行同样有 hover「重新生成」。弹窗列出将被作废的后续阶段，确认后 `POST …/retry` 带 `{stage}`；无单选「仅本阶段 / 连同后续」。
- **底部终态按钮**：取消后「从当前阶段重试」、失败后「重试本阶段」仍不带 `stage`，只续跑停住的那一步。重试会清掉上次取消留下的 `cancel_requested`，不会刚入队就再次停止。页头「正在停止当前生成」只在取消尚未落定、任务仍进行中时显示。

### 接口与状态

| 动作 | 接口 | 结果状态 |
| --- | --- | --- |
| 采纳当前步 | `POST /api/projects/{id}/ai/operations/{op}/advance` | 下一 leg `queued` / `running`，或最后一步 `succeeded` |
| 提交调整说明 | `POST …/revise` body `{feedback}` | `revising`，流式出该阶段问题 |
| 重试当前失败/取消步 | `POST …/retry` | 从 `current_stage` 续跑，保留已完成步骤 |
