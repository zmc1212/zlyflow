# H3 Director 一采审片后确认二采开发计划

日期：2026-09-28
状态：2026-09-28 用户选择路线 2，保留原节点与工作流，独立适配包及 W4A8 加载修复已部署。单段 1/2 MP、双段一采与 1 MP 二采已出片，缓存缺失和重复预览均严格拒绝。工作台确认接口、检查点、子任务与三处结果面板已开发，234 项后端和 392 项前端测试通过，真实业务子任务交付与数据库重新打开验收通过。登录后的桌面及剩余恢复验收尚待完成，入口继续隐藏。见 [业务接入记录](H3确认后二采业务接入-2026-09-28.md)。本计划替代此前“默认一采后自动二采”的交互方案。

## 1. 目标与产品流程

原 `director-refine-accel@1` 与旧 director_加速版保持不变。复制为独立 `director-confirm-accel@1` 配方（拟注册 ID `minimax-h3-director-confirm-accel-r2v`）；仅副本中的 Director class_type 改为 `ZlyH3ConfirmedDirector`，保留副本节点数字 ID、作者模型、LoRA、采样步数、调度器和降噪强度。新模式通过全部验收后再独立注册，不覆盖旧工作流映射。

新工作流统一使用以下流程：
1. 选择「H3 Director 二采加速版」，输入参考图、提示词、时长与比例，点击「生成一采预览」。
2. 一采成功即结束本次 GPU 任务，展示可播放、下载的一采原片，状态为「一采完成 · 待确认二采」。
3. 用户可直接使用一采，也可选择二采目标画质（1 MP / 2 MP，默认 2 MP），点击「确认并生成二采」。
4. 创建独立的二采子任务，复用已确认的一采缓存，不重新生成一采。
5. 成功后并列展示「一采原片」「二采精修版」，默认预览二采，但不覆盖一采文件。

移除新建表单中的“自动二采”开关。目标画质移动到一采结果的确认操作区。首版不新增自动连续二采模式、不新增精修强度，不自动叠加 RTX 超分。

二采成功不自动替换用户已采用的成片：二采作为关联候选，沿用既有“采用”操作；用户选择后才更新制作使用的素材。生成一采继续遵循既有的一采采用规则。

覆盖创作页、导演台单镜、选中镜及多段整集任务。多段按原生成组确认：查看拼接的一采预览后，一次确认处理该候选的全部生成组；首版不另加逐段精修选择。

## 2. 先验证远端节点的真实执行协议

当前已核对远端节点存在 confirm_first_pass。说明为：开启时，没有精确匹配缓存则只生成一采；已有缓存则跳过一采继续二采。

这不是无条件暂停开关：如果缓存已经存在，第一次业务提交也可能直接触发二采。因此不能简单把 confirm_first_pass 设为 true 后重复 Queue。

实施第一步读取当前远端 Director 节点及其前端“确认二采”使用的实际源码/接口，并验证：
- 一采缓存指纹、缓存命名空间、有效期以及远端重启后的保留情况。
- 确认操作如何查询缓存、是否有显式一采/二采动作、如何处理重复提交。
- 一采预览阶段实际输出节点、report 和缓存标识；不能继续假定节点 7 永远代表已完成二采。
- 相同种子、不同输出前缀、不同 Director unique_id 是否影响缓存归属。
- 目标画质改变是否仅影响二采、不使一采缓存失效。
- 首次任务与重试不会因缓存命中越过用户确认；确认后缓存缺失不会静默重跑一采。

优先接入原生确认接口与缓存查询机制，不自行猜测指纹或根据 MP4 存在推断 latent 可用。冻结经验证的协议及测试样例。

发布门槛：原生自动行为不满足严格确认。按用户选择，在当前远端的 `custom_nodes` 新增独立 `zly_h3_confirmation` 包，只让复制的工作流引用。禁止修改原节点源码、替换原 class 注册、全局 monkey patch、覆盖原工作流或新增第二套 ComfyUI。新增包部署和必要的空闲重启属于本路线；不得中断已有用户任务。

适配协议 `zly-h3-confirmation@1`：
- `preview_only`：忽略命中缓存的自动升级行为，执行层禁止调用二采；生成后核实真实 latent 缓存保存成功。
- `refine_only`：校验原实例、cache_key 和冻结 graph 的 source_revision；实际加载失败即报错，执行层禁止任何一采调用。
- 通过私有函数作用域复用固定版本作者执行器，不改变作者模块全局函数。固定执行器/缓存/输出模块哈希，不兼容则拒绝新适配流程，原工作流继续可用。
- 专用缓存命名空间与系统文件锁隔离任务，禁止覆盖已完成的一采来源；重生成预览使用新 cache_key。
- 输出结构化阶段报告（实际一采/二采次数、缓存段、复用段、源修订、实例身份），不能以 ComfyUI success 或 MP4 存在作为阶段证据。
- 在真实实例通过阶段约束、预检后缓存丢失、多组与重启验证后，再接任务层及界面；未通过不发布按钮。

用户已说明 asym_w4a8_int8 加载问题已修复；重新验证当前实例，不再沿用旧故障结论，也不更换模型。

## 3. 后端任务、接口与快照

继续使用当前任务表及 JSON payload，不新增数据库表。

将业务确认状态与执行任务状态分开：
- 第一阶段任务正常 completed，结果为一采视频；另存 refinement_state=awaiting_confirmation。
- 确认创建关联子任务，子任务 queued/running/completed/failed/cancelled；原一采任务保持完成。
- 失败或取消不删除原片，不影响原片播放、下载与采用。
- 只有报告证明二采已完成时才记录二采成功，不能以 ComfyUI status=success 或单个视频输出作为充分条件。

新模式任务使用独立配方 `director-confirm-accel@1` 与节点协议 `zly-h3-confirmation@1`；替代此前拟定的同模式 `director-refine-accel@2`，避免混淆两套工作流。保留旧 `director-refine-accel@1` 解释与历史重试语义，不迁移旧自动二采任务。

持久化内容：
- 来源任务/候选 ID、创建用户、协议/配方版本、固定 seed。
- 完整一采 API graph、有效参数、原参考素材身份及上传文件信息、时间轴和生成组顺序。
- 远端实例身份、原生缓存标识/指纹、已验证的阶段报告。
- 一采与二采媒体 URL、实测尺寸/帧率/时长，各组执行进度与子任务 ID。

新增确认接口：
- 创作任务：POST /api/jobs/{job_id}/refine。
- 导演任务：POST /api/projects/{project_id}/jobs/{job_id}/refine。
- 请求只接受 refine_quality（1.0 或 2.0，默认 2.0）、source_revision 和幂等请求标识；不接受改写一采 seed、提示词、参考图或模型。
- 返回二采子任务 ID，沿用现有鉴权、CSRF、队列和任务通知。
- 同一来源有进行中的二采时返回已有子任务；来源已变化返回 409；无一采、非本工作流或缓存无效返回可操作错误。
- 不从当前页面设置或最新镜头数据重建 graph，必须使用已确认候选的冻结快照。
- 管理设置切换到另一个 ComfyUI 后禁止跨实例继续旧缓存；提示恢复原实例或重新生成预览。
- 再次生成二采允许选择另一个目标画质并新增候选，保留上一版；普通重试只重试失败子任务。

多组任务逐组记录并即时保存二采结果。重试复用成功组，仅处理未完成组；若其中任何待处理组缓存失效，停止并告知，不静默生成新的第一遍。全部成功后按实际媒体参数合成，不能拿一采尺寸处理二采文件。

## 4. 界面与异常交互

仅对新工作流显示阶段化操作，全部使用 Ant Design 与现有主题变量，不改导演台对话创作室样式。

一采完成卡：
- 标签「一采预览」、播放、下载、既有采用入口。
- 目标画质选择与「确认并生成二采」按钮。
- 二采运行时展示子任务进度，禁止重复确认；允许按现有机制取消。

二采完成卡：
- 一采/二采并列或 Tab 对比，显示实际分辨率和生成时间。
- 二采候选提供“采用”，不静默替换用户已选素材。
- RTX 超分保留在成片的独立操作入口。

缓存失效：
- 提示「一采缓存已失效，原片仍可使用；继续二采需要重新生成一采预览」。
- 只提供明确的“重新生成一采预览”，返回新预览后再次由用户确认。
- 不把原片 MP4 当作 latent 缓存，不自动从 MP4 编码代替作者原版流程。

修改提示词、参考素材、时长或比例属于新的一采任务。用户仍可对旧候选按旧快照确认二采，不能把新输入混入旧候选。

## 5. 测试、验收与上线

自动化：
- 旧 `director-refine-accel@1` 历史语义与旧加速版 graph 不变；新 `director-confirm-accel@1` 默认只产生一采。
- 默认参数、API 权限、幂等确认、并发冲突、来源版本冲突。
- seed=0、原素材顺序、原始 graph、缓存实例绑定与重试均保持一致。
- 缓存存在/缺失/过期/执行前丢失、服务重启、页面刷新、断线恢复。
- 首次任务缓存已存在时仍不能未经用户确认二采。
- 一采输出不误判二采；二采失败或取消保留原片；手动采用行为。
- 多组部分成功后的重试与不同实际分辨率合成。
- 目标画质仅在确认区显示；按钮、状态与浅暗主题交互。

真实远端：
1. 复验原版二采模型可加载。
2. 用固定素材和种子生成一采，确认没有执行二采采样，且一采视频可播放。
3. 用户确认模拟操作后生成 1 MP 二采，通过节点执行报告确认复用缓存、未重跑一采。
4. 同一来源生成 2 MP 二采，保留各版结果。
5. 验证重复提交、多段、远端/后端重启恢复及缓存失效路径；只操作专用测试缓存，不清理用户缓存。
6. 与原生“先一采再确认”流程使用相同参数比较 graph 和输出，记录耗时与媒体参数。

运行相关后端测试、前端测试和 pnpm --dir frontend build；在 5173 桌面浅色/暗色页面验收创作页及导演台流程，更新规范目录下的参考截图。

同步更新 README、功能说明与扩展指南、ARCHITECTURE、导演台流程文档及接入记录。测试产物放入已忽略目录，清理临时产物。

只有模型、严格确认协议、缓存复用、双阶段结果及桌面验收全部通过后，才解除新工作流 hidden_from_catalog。旧默认工作流不变。回滚隐藏新建入口与确认操作，保留一采/二采媒体、任务记录和历史协议读取能力。
