## 已核实证据

- 从 `provider_bridge.comfy_row()` 读取实际实例 `http://192.168.10.54:8188`，未切换配置。节点定义、扩展脚本和缓存状态接口均可访问。
- 用户提供的上游仓库固定到 [a8938feb6ada0b7981f977b1a6be59341f0c6d10](https://github.com/AIMixer/ComfyUI_MiniMaxH3_Director/tree/a8938feb6ada0b7981f977b1a6be59341f0c6d10)。远端 `minimax_refine.js` 与该提交文件字节 SHA-256 一致：`75db6e8132828147d06dda40ad18cc952ab9a6eee5d64d4884b6be1c187e90dd`。这只能确认前端一致，不能据此断言远端 Python 未做本地修改。
- 原生前端通过 `POST /minimax/director/first_pass_cache_status` 查询，另有清缓存接口；没有独立确认执行请求。“确认二采”是状态文案，后续依赖普通 Queue。探针不调用清缓存或 Queue。
- 原生查询要求数字 `node_id`，非数字返回 400。专用查询 ID `2147483000`、固定 seed 0、虚拟参考文件在 1 MP 和 2 MP 均返回 200、`exists=false`、`matches=false`、`current_seed=0`、`can_confirm_refine=false`、`confirm_refine_reason=first_pass_mismatch`、逐段 `<missing-cache>`。未上传文件，也未提交 GPU 任务；这仅验证查询协议，不证明真实缓存复用。

## 执行层缺口

以下结论来自固定提交源码，远端 schema 与 tooltip 的行为描述也与之相符：

1. [`director/executor_core.py:616`](https://github.com/AIMixer/ComfyUI_MiniMaxH3_Director/blob/a8938feb6ada0b7981f977b1a6be59341f0c6d10/director/executor_core.py#L616) 先加载缓存，再由是否命中决定 `skip_first_sample` 和 `hold_after_first`。首次业务请求已有缓存时可直接进入二采；工作台按钮状态无法强制只跑一采。
2. [`director/segment_cache.py:1037`](https://github.com/AIMixer/ComfyUI_MiniMaxH3_Director/blob/a8938feb6ada0b7981f977b1a6be59341f0c6d10/director/segment_cache.py#L1037) 在 meta/latent 缺失或指纹不同返回 `None`；执行层随后重新一采。因此缓存预检通过、执行前丢失的竞态无法靠工作台二次查询解决。
3. 缓存目录为 ComfyUI output 下 `minimax_seg_cache/<node_id>`，文件按段索引保存 `.pre.meta.json` 与 `.pre.av.pt` 等。`nodes/director.py` 将 `unique_id` 作为缓存命名空间。输出文件前缀不能隔离该缓存；本轮不改作者节点 ID。
4. 一采指纹包含段身份、seed、采样设置、SelfLift、Semantic Bridge；`first_pass_cache_fingerprint` 明确排除 refine 参数，因此目标 MP 不参与该指纹。缓存文件是磁盘数据，未发现此模块的 TTL；远端重启持久性、实际清理策略仍未实测，不能承诺永久有效。
5. 执行器有等待确认报告，Director 将 `held_for_confirmation` 传给输出打包的 `block_final_images`。不能沿用旧配方“节点 7 存在就算二采成功”的解释。实际阶段输出与采样报告仍须在协议扩展后冻结验收。

结论：上游当前实现不满足计划要求的严格阶段约束。维持 `hidden_from_catalog=True`，不新增 `/refine` API 或确认按钮，不把 `@1` 改解释为 `@2`。移除 refine 分支只生成视频也不能自动证明已留下可复用的一采 latent。

## 最小上游支持方案（提案，未部署）

保留现有节点 ID、模型、LoRA、采样参数及默认旧行为，在原节点内增加版本化执行合同：

- 显式 `preview_only`：无论同参数缓存是否存在，绝不执行二采；返回已冻结的一采缓存身份和可用预览。
- 显式 `refine_only`：必须带服务端签发的缓存身份/修订号；在执行边界原子加载或持有缓存，缺失、修订不符或损坏直接报可识别错误，禁止回退一采。
- 业务缓存身份独立于可视节点 ID；实例身份与重启策略明确，避免不同任务共享节点 12 的同段文件覆盖。
- 返回结构化逐段报告，包含请求阶段、实际阶段、一采/二采是否执行、缓存身份/修订、有效采样快照与输出媒体参数；多组支持保留成功组并恢复未完成组。
- 查询响应包含协议版本与能力声明，但不能用查询代替执行时约束。能力、竞态、重启和重复请求测试通过后才实现工作台 `@2` 子任务/快照/确认接口/候选采用和双主题界面。

该提案需上游提供或另行授权维护远端节点；本计划明确禁止擅自修改远端。没有更换模型，也没有把 MP4 编码成 latent 代替作者流程。
