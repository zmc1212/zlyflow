# 导演台设计图生图提示词 v4（系统对齐版 · 浅色/暗色双主题 · Agent 剧本创作模式）

> **双主题**：同一套功能区块、布局、状态和文案必须分别生成浅色版与暗色版，不能让模型自行混合色板。
> - **暗色版**：工作台全局基线为画布 `#0f1115`、表面 `#171a20`、抬升表面 `#1e2229`；对话创作室的 cinema 层可使用更深的画布 `#0b0d12`、表面 `#12151c/#171b24`、蓝紫辉光渐变。产物在 `docs/导演台设计图/`。
> - **浅色版**：工作台全局基线为画布 `#f8f9fa`、表面 `#ffffff`、抬升表面 `#f4f6f8`；对话创作室使用 `#fafafb/#f1f2f3` 的白卡层级、品牌渐变 `#4d6bfe→#7b5bff`。产物在 `docs/导演台设计图/浅色/`。
> **主题映射**：工作台 `data-theme="dark"` → 暗色提示词；`data-theme="light"` → 浅色提示词。代码实现对应 `frontend/src/index.css` 的 `--studio-*` / `--director-*` 与 `frontend/src/director/guided-flow.css` 的 cinema 双主题层。
> **基线与增强原则（两版通用）**：参考截图只是「现状基线」，不是最终稿——设计稿 = 在现有代码的信息架构上做合理演进：除还原截图功能外，可实施标注**【增强】**的设计点（每一项都已核对代码数据模型字段，架构可支撑）；未标注处保持截图现状，禁止无数据支撑的发明。澄清问题必须保留“输入你的想法”自定义入口，剧本封面只在用户上传后出现。
> **用法**：每张图 = 「通用结构前缀 v4」+「主题前缀 v4（dark 或 light 二选一）」+「v4 系统对齐补丁」+ 1 个「分镜提示词」，附上对应参考截图（`docs/design-ref-director/`，截图仅用于锁定功能区块与文案，不锁定视觉风格）。
> **编号规则**：提示词编号 = 参考截图编号（17–25 = agent 剧本创作模式全状态；01–11 其他页面暂缓，需要时按同样模板补写）。
> **基线宽度 1920**：设计图与前端界面验证均以 **1920×1080** 为基准（生成图若为其他 16:9 尺寸，按 1920 等比缩放验收）。
> **v3 比例修正（2026-09-13）**：v2 生成图文字整体偏大（画布被模型按 1672×941 自选尺寸渲染，px 值被当作绝对像素）。v3 在通用前缀中内置 1920 视口声明、字号上限（≤28px）、每行字符数自检（正文一行 55–70 字）与结构尺寸锚点；重生成后按此验收。
> **版本**：v1 浅色基准稿已归档至 `docs/导演台设计图/v1-浅色基准/`；v4 在 2026-09-13 依据当前系统快照整理。
> **v4 调用顺序**：每张图实际拼接为「通用结构前缀 v4」+「主题前缀 v4（二选一）」+「v4 系统对齐补丁」+「对应编号分镜提示词」。文中旧的「通用风格前缀」均按此顺序解释，不能单独使用。

## 通用结构前缀 v4（两主题共用）

> 本节只定义当前系统的结构、排版、状态与交互表达；颜色、表面、边框、阴影和辉光必须从下面的「主题前缀 v4」二选一注入。旧提示词中的「通用风格前缀」统一按 v4 调用顺序解释。

```text
你是一名顶级产品设计师，为「ZLY AI 视频工作室」的导演台重新设计高保真桌面端 UI 概念稿。设计语言参考专业视频工作台（媒体优先、极简界面、真实桌面软件的排版密度）；电影感只作为暗色主题的视觉增强，浅色主题保持清晰、轻量的白卡层级。硬性要求：
- 画布按 1920×1080 桌面视口设计（16:9 横版完整界面），不是插画、不是海报、不要浏览器窗口边框。下文所有 px 都是 1920×1080 视口下的真实 CSS 尺寸；若输出为其他 16:9 分辨率，所有元素（文字、控件、图标、留白）必须按同一比例整体缩放，禁止单独放大文字或控件。
- 主题色板与表面层级必须使用下面的「主题前缀 v4」，本节不重复指定主题颜色；同一张图只允许一种主题。
- 品牌强调色只使用当前主题前缀指定的主色：暗色可使用克制的蓝紫辉光，浅色使用清晰描边与轻投影；不要把两套强调色混用。
- 媒体优先：视频画面/缩略图区块大而醒目（16:9、圆角 12px、跟随主题的边框）；空态与占位使用当前主题的浅/深层级 + 细线图标；时间码、时长、字数等数字一律等宽字体。
- 排版按真实桌面软件 100% 缩放截图的密度执行，不是演示海报。字号体系（1920 基准）：微标签/角标 11px 加宽字距（中英配对，如「生成任务 TASKS」）；正文、按钮、输入框 13–14px；卡片标题 16–18px；区块主标题 20–24px 加粗、字距略收紧；全图任何文字（含成稿卡大标题）都不得超过 28px。比例自检：13px 正文一行应容纳约 55–70 个中文字符，区块主标题宽度约占画布宽度 10–15%；若一行正文只放得下二三十个字、或标题大得像海报字，就是画大了，必须整体缩小。每张图仍要有一个明确视觉主角，主角感靠构图位置、渐变辉光与媒体区块尺寸表达，不靠放大文字。
- 结构尺寸锚点（1920×1080 下）：顶栏高约 64px；左侧图标栏宽约 72px；任务栏卡片宽约 400–440px；卡片内边距 20–24px、区块间距 16–20px；底部浮动输入条高约 72px、距画布左右约 24px。
- 圆角体系：卡片 16px、输入条与任务行胶囊 24px、小按钮 10px；底部浮动输入条的透明度、背景和边框跟随当前主题前缀。
- 功能区块必须与下面列出的完全一致，不可增删；中文文案只使用我给出的原文，清晰锐利无乱码。
- **基线与增强规则**：参考截图是「现状基线」，本设计稿要在同一信息架构上做更合理的设计演进。凡标注**【增强】**的区块是本轮设计的加分项，必须呈现——它们都已获产品数据模型字段支撑（镜头视频/首帧 URL、画风封面图、角色/场景图片、镜头时长等），不是凭空编造；未标注的区块以参考截图的状态为准。除【增强】外不得发明界面上不存在的功能。
- **功能与状态逻辑以参考截图为准**：截图记录的是真实运行状态（任务行数量、按钮可用态、标签文字等），若本文字描述与截图冲突，以截图为准；只允许重新演绎视觉风格与实施【增强】，不允许改动信息架构与交互逻辑。
- 克制：渐变、辉光或阴影只用在关键处；留白要大方；不要密密麻麻的灰色表单框，不要在同一张图混用浅色与暗色，不要默认组件库风格。
```

## 主题前缀 v4（二选一，必须显式指定）

每次生成只选择一个主题前缀，并在提示词第一行写明 `theme=dark` 或 `theme=light`。同一编号需要分别生成两张图，不能用一张“浅暗混合版”代替。

### 暗色主题前缀 v4

```text
theme=dark
使用 ZLY AI Video Studio 当前暗色主题 token：全局画布 #0f1115，顶栏/Chrome #13161b，普通表面 #171a20，抬升表面 #1e2229，输入字段 #20252d；主文本 #f3f5f7，次级文本 #9ba5b1，边框 rgba(255,255,255,.10)，主色 #435ce8，弱主色 rgba(67,92,232,.10)。
若画面属于导演台对话创作室 cinema 层，可将画布加深为 #0b0d12，表面使用 #12151c 与 #171b24，强调色使用 #5b7cff→#8b6aff 的渐变；这只是 cinema 层的局部增强，其他区域仍保持系统表面层级。
暗色媒体预览允许接近黑色，但工作区、卡片、输入条、Modal、Select、Dropdown、Tooltip 等区域必须有可辨识的表面差异；辉光只用于当前选中项、进度、关键按钮和状态焦点，不使用厚重灰色投影。
```

### 浅色主题前缀 v4

```text
theme=light
使用 ZLY AI Video Studio 当前浅色主题 token：全局画布 #f8f9fa，顶栏/Chrome #ffffff，普通表面 #ffffff，抬升表面 #f4f6f8，输入字段 #f2f2f3；主文本 #171a1f，次级文本 #65707c，边框 rgba(15,23,42,.08)，主色 #4d6bfe，弱主色 #eef1ff。
若画面属于导演台对话创作室 cinema 层，使用 #fafafb 的页面背景、#f1f2f3 的画布、#ffffff 的卡片和 #f7f8f9 的内嵌表面；强调色可使用 #4d6bfe→#7b5bff 的品牌渐变，辅助强调色遵循 #0285ff / #0170dd / #e9f3ff。
浅色卡片使用极轻的层级阴影和清晰边框，禁止出现暗色卡片、近黑媒体外的纯黑区域或暗色玻璃拟态；Modal、Select、Dropdown、Tooltip 等传送到 body 的浮层必须保持白色表面、深色文字和同一套主色。
```

### 两主题共用的生成约束

```text
主题前缀已经指定的颜色、表面、边框、阴影和强调色优先级最高；不要自行添加第三套色板。浅色版与暗色版必须保持相同的布局、阶段顺序、任务数量、状态文案、按钮文案和交互逻辑，只改变主题表达。输出中不要出现“浅色/暗色切换演示”或左右分屏对照，单张图只呈现一个主题。
```

### 分镜视觉描述的主题替换规则

17–25 号分镜提示词中的「深色画布」「深色卡」「玻璃拟态」「辉光」「深色内凹」等词，是视觉语义，不是要求所有版本都使用暗色。使用 `theme=dark` 时按暗色主题前缀和 cinema 层渲染；使用 `theme=light` 时按下表替换，布局与信息不变：

| 分镜描述 | `theme=dark` | `theme=light` |
| --- | --- | --- |
| 画布/工作区 | `#0f1115`，对话 cinema 可用 `#0b0d12` | `#f8f9fa`，对话 cinema 使用 `#fafafb/#f1f2f3` |
| 卡片/任务栏表面 | `#171a20/#1e2229` 或 cinema `#12151c/#171b24` | `#ffffff/#f4f6f8` 或 cinema `#ffffff/#f7f8f9` |
| 玻璃拟态输入条 | 半透明深色 + 亮边 + 克制辉光 | 半透明白色 + 轻边框 + 极轻阴影，不出现暗色玻璃 |
| 渐变辉光/发光描边 | `#5b7cff→#8b6aff`，只强调焦点 | `#4d6bfe→#7b5bff`，以清晰描边和轻阴影为主 |
| 深色内凹/浮雕块 | `#1e2229` 与低透明亮边 | `#f4f6f8` 与低透明深色边框 |
| 弹窗背景压暗 | 黑色半透明遮罩 + backdrop blur | 深蓝灰半透明遮罩 + backdrop blur，底层仍保持白色层级 |

浅色版本禁止保留「深色大卡」「近黑背景」「蓝紫强辉光」的字面效果；暗色版本禁止把所有表面压成纯黑。两版都必须保留真实系统的对比度、状态色和可读性。

## v4 系统对齐补丁（替换旧前缀中的冲突项）

生成前将本节整体追加到通用前缀末尾。它解决旧提示词最容易导致的“看起来漂亮但不是当前系统”的问题：

```text
【系统真实状态优先】这是一张 ZLY AI Video Studio 导演台的产品界面概念稿，信息架构必须来自当前工作台，而不是泛化的 AI 产品模板。导演工程路由是 /director/:projectId；桌面端支持 plan 与 timeline 视图，导台 2 为 /director2。当前 Agent 剧本创作按实际状态展示阶段：研究、脚本、美术风格、角色、场景、分镜、配音、配乐、媒体；但完成态任务栏只展示真实返回的环节，不要擅自补齐不存在的阶段。

【状态与数据绑定】所有进度、耗时、镜头数、时长、比例、状态文案必须看作后端任务状态的直接回显：阶段状态只能使用 waiting/running/completed/failed/cancelled 的视觉等价物；运行中的阶段显示取消入口，完成阶段显示摘要；重新生成必须明确影响范围。分镜时长来自 shot.durationSec，镜头缩略图来自 shot.videoUrl 或首帧 URL，画风缩略图来自目录封面字段，不能凭空创造图片或按钮。

【澄清问题卡真实性】每张澄清问题卡必须逐行渲染后端返回的全部预置选项（推荐项也保留）并额外保留一行“输入你的想法”自定义输入项；不能因为画面紧凑而缩成三选项。预置项数量由当前问题数据决定，设计图至少出现四行，若后端返回四个预置项则应出现五行。不能把自定义项改成不存在的模型选择器。自定义项应呈现可输入的单行文本框（空值时显示“输入你的想法”），并与单选状态绑定。

【媒体来源真实性】没有 `recipe.script.coverUrl` 时，剧本阶段只能使用主题背景、渐变和 UI 空态，不绘制外卖小哥、人物、街景、雨夜或摄影棚等叙事背景图；这些内容即使出现在创意文案中，也只能作为文字。只有当 `coverUrl` 已上传时，才在封面控件、工程卡片或成稿卡展示该用户图片，不能替换成模型自造图片。

【交互真实性】只绘制当前截图能证明或文档明确列出的控件。按钮必须区分 primary、secondary、disabled；弹窗使用 Ant Design Modal 的真实层级与关闭行为；提示、Select、Dropdown、Tooltip 等传送到 body 的浮层必须与当前主题一致。不要把 ComfyUI 节点参数、模型名、采样步数、seed、设备信息放进创作表单。

【主题真实性】默认浅色和暗色都要能独立生成。暗色使用 #0f1115 画布、#171a20 表面、#1e2229 抬升表面、#f3f5f7 主文本；浅色使用 #f8f9fa 画布、#ffffff 表面、#171a1f 主文本。主题切换由根级 Provider 与 data-theme 驱动，组件不能各自维护主题。暗色媒体预览可近黑，其他区域必须保留表面层级；浅色禁止残留暗色卡片。

【信息密度与响应式】1920×1080 只作为桌面基准；同时在画面角落以小型 device hint 表示 390px 移动端会将左任务栏折叠为顶部进度条、底部输入条变为全宽、镜头列表改为单列。桌面不要按海报排版，正文 13–14px，标题 ≤28px；中文文案必须锐利、无乱码、与参考截图逐字一致。

【禁止项】不要新增排行榜、聊天侧栏、假数据图表、模型选择器、浏览器边框、营销口号、没有数据来源的媒体卡片；不要改变参考截图的阶段顺序、任务数量、按钮文案和交互逻辑。设计演进只体现在层级、间距、可读性、产物预览和主题适配。
```

### 当前版本优先级

1. 先锁定真实截图中的布局、文案和状态，再做颜色、层级和动效优化。
2. 任何“增强”必须能指向当前数据字段或已有交互；无法指向字段的内容删除。
3. 一张图只突出一个视觉主角：问题卡、直播卡、进度网格或完成产物，避免标题与数字同时抢焦点。
4. 输出提示词时明确 `dark` 或 `light`，不要让模型自行混合主题 token。
5. 设计图验收增加三项：Ant Design 浮层主题一致、移动端折叠逻辑可解释、阶段状态与真实截图一致。
