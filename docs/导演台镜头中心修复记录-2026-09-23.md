# 导演台镜头中心第一版修复（2026-09-23）

## 本版结果

恢复「剧本 → 镜头 → 声音 → 合成」主流程。镜头保持可编辑，Director 提示词大师放进镜头检视器的「提示词与视频」页签。点击「AI 优化本集提示词」生成整集扩写预览，检查并保存后，按来源镜头查看关联生成段并局部生成视频。整集扩写仍保留上下文；本版未实现单镜独立的 Director 故事规划。

生成段通过 `source_beat_ids` 关联原镜头，不把生成段替代成另一套用户必须维护的镜头。选中镜头后仅展示其关联生成段；一个连续生成段可对应多个源镜头。

## 数据修复与失败处理

- 删除工坊初始化时「每个非空文本行变成一个分镜」的兜底。只读取明确的镜头/场景块；没有结构的正文提示去内容库规划镜头，不猜测拆分。
- 精确匹配旧逐行结果时，提供「按剧本恢复镜头」。事务锁及剧本/镜头 ID 校验防止覆盖并发编辑，旧 beats、方案、制作状态写入 `data.shot_structure_backups`。原媒体与任务不删除，旧方案须按新来源重生成。
- 场景块只在有动作或对白时形成镜头；未明确场景的块不继承上一个场景，留给用户绑定。识别台词前缀中的说话人，避免默认第一个角色和重复前缀。
- 实际修复项目 `proj-0f9c8015281149f0` 的第一集 `ep-4d89a8df80a4`：26 条逐行镜头恢复为 6 个场景块，32 秒为既有时长估算，并不代表完成了导演剪辑设计。恢复及场景/说话人校正均保存了备份。
- 已选择的参考图身份与 `<Picture n>` 顺序由程序形成公共主体定义，避免模型漏写公共设定导致整次失败。扩写上下文只携带选中及镜头绑定的资产。
- 失败任务保留已有流式输出，打开面板可接回最近失败任务；修复来源前阻止对旧逐行结果再次扩写。

## API 与文件

新增 `POST /api/projects/{project_id}/episodes/{episode_id}/restore-script-shots`，请求包含 `script_text` 与 `beat_ids`，冲突返回 409。详情的 `data.shot_structure` 提供旧结构检测和是否可恢复。无数据库表迁移，不改工作流节点、模型地址或端口。

后端：`script_parser.py`、`project_detail_service.py`、`project_router.py`、`director_story_design.py`、`prompt_expansion_service.py`。前端：`api.ts`、`EpisodeWorkshopPane.tsx`、`ProductionPanes.tsx`、`PromptAuthoringPanel.tsx`、`production.css`。测试：`test_workshop_shot_structure.py`、`PromptAuthoringPanel.test.ts`；`.gitignore` 放行新增正式后端测试。

## 兼容性与回滚

现有镜头、手动编辑、历史视频和旧任务保留。普通逐镜工作流保留原功能；Director 入口位置改变，路由 tab key 保持兼容。

代码回滚仅撤回本记录列出的增量，勿整文件覆盖工作区原有未提交修改。数据回滚需在暂停该集编辑后，核对备份时间，将指定 `shot_structure_backups` 的 beats/方案/production 恢复并同步 `shots_count`；当前尚无面向用户的备份恢复按钮。回滚前再次备份当前数据，不能删除历史媒体或任务。
