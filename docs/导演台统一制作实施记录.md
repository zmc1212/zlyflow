# 导演台统一制作实施记录

日期：2026-09-22。适用范围：桌面端分集工坊，普通逐镜与 Director 连续画面。

## 实现与使用

分集工作区按「剧本 → 画面 → 声音 → 成片」排列，可自由切换。旧 `tab=script/shots/dubbing/compose` 继续有效；`unit` 和 `source` 保存选中画面及来源定位，刷新和浏览器返回可恢复位置。

- 剧本保留原文与来源 Beat，可编辑来源并跳转对应画面。
- 画面承载完整提示词方案、参考资产、Part/Segment 或逐镜列表、素材预览及采用操作。公共主体定义集中展示，选中段自动展开对应 Part；Director 不再显示另一套 Beat 待生成列表。
- 声音默认保留原声。需要补配时，先在折叠工作区生成音频，再选择来源台词、已采用素材、素材内起止秒数和叠加／替换方式。超过区间的台词必须调整，替换会静音该区间的整个原音轨。
- 成片读取采用时间线，显示缺口、方案过期或声音需对齐等阻塞原因。局部采用后旧片仍可播放，新导出完成后再切换当前成片。

## 数据与事务

`data_json.production.schema_version=1` 保存 `revision`、`active_mode`，以及 `modes.shot/director` 独立的素材索引和 `versions[plan_key]`。每个版本包含 `adopted`、`audio`、`exports`。不改数据库表，不复制媒体文件。

任务固定 `production_context`（制作方式、方案键、完整方案快照、完整单元范围），素材记录任务、工作流、URL、实际帧数／帧率／时长及单元区间。空白范围首次成功可自动采用；重做结果只成为候选。旧任务迟到仍保留候选，不覆盖新方案采用版。自动超分结果作为单独候选保留。素材身份包含内容 SHA-256：重试得到相同字节不会重复登记，重试生成不同内容则保留为新候选，避免同任务 ID 偷换已采用画面。

新接口：

| 接口 | 作用 |
| --- | --- |
| `GET /api/projects/{project_id}/episodes/{episode_id}/production?mode=shot|director` | 方案、素材、采用清单、声音、时间线、历史导出和就绪原因 |
| `PATCH .../production/mode` | 切换制作方式，保留两种方式数据 |
| `PATCH .../production/adopt` | 以 `material_id` 采用素材完整覆盖范围 |
| `PATCH .../production/audio` | 更新声音编排列表，服务端解析音频来源并校验区间 |
| `POST .../compose` | 携带 `expected_revision`、`production_mode`，冻结时间线与声音后排队导出 |

PATCH 均须携带 `mode` 与整数 `expected_revision`；分集事务内 `SELECT ... FOR UPDATE` 校验版本，冲突返回 409。导出保存采用与声音指纹，迟到的导出只记为历史。配音同步也从加锁后的 JSON 合并，避免覆盖并发采用。

普通模式方案键包含剧本、视觉来源字段、参考槽位与相关资产指纹；Director 使用已保存方案 ID、revision、source_fingerprint。声线配置和资产排序不再误使视觉方案过期。已保存旧指纹通过原预览任务的不可变来源快照兼容比较，不跳过现有 schema 门禁。

## 媒体边界

不使用旧 `outputStart` 的 chunk 起点伪造 Segment 起点。新素材通过实际提交帧数、渲染报告和 ffprobe 验证；多段帧数不匹配时只允许完整范围使用。连续选区即便被渲染器拆成多个 chunk，也只形成一个可采用候选。

成片按采用区间解码裁切，保留原声并仅在指定区间叠加／替换补配。拼接前裁掉 AAC 填充，避免逐段累积编码延迟。媒体缺失、区间越界、实际音频过长会明确失败，不静默交付残缺视频。

## 迁移与回滚

读取旧分集先建立兼容投影，首次制作写操作在分集事务内落盘；`legacy_imported` 保证重复执行不重复导入。旧字段保留。旧 Beat Take 转为普通模式引用；Director 结果只有任务中的方案 ID、版本与覆盖范围可核实时归属当前方案，无法归属的结果仅进入历史。缺乏可靠切点的旧整片不自动拆分。

回滚应用代码时保留 `data_json.production` 和新任务 payload，旧代码可忽略这些新增字段。新采用状态不回写覆盖旧 Beat 视频；因此回退旧界面会显示旧采用版本，不能把旧界面当作新采用清单的权威。需要再次升级时可继续读取生产数据；不要删除新字段或批量重生成。
