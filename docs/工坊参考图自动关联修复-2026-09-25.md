# 工坊参考图自动关联修复（2026-09-25）

## 原因与结果

资产库保存人物／道具图片，工坊原先另存组级 `reference_slots`；规划、后补图和换图没有统一解析这两份信息，导致资产有图但最终视频参考为空。H3 生成保存的是候选稿，旧界面又把候选区放在空编辑器下方，让“生成完成”看起来没有结果。

统一工坊 v7 现在由后端 `workshop_references.resolve_state` 解析当前资产、镜头绑定和造型；读取、规划候选、写词、采纳、保存与视频预检共用同一有效参考。此逻辑适用于所有项目和新剧集，不包含项目、人物或镜头 ID 特例，不依赖一次性数据库回填。

## 行为与边界

- 新规划组采用 `reference_policy=auto`，按组内镜头顺序选取绑定人物／道具，去重并分配 Picture 编号；不自动加入场景或无关资产。
- 后补图片、更新图片和镜头绑定变化在下一次读取时重新解析。GET 不写数据库；显式保存仍经过剧集行锁及版本校验。
- 精确且唯一的资产名称可补全未解析的绑定；用户明确移除的绑定由 `workshop_manual_bindings` 记录，不会按名称重新加回。
- 造型选择优先显式绑定，随后使用唯一匹配的时代造型。缺图、重名、多造型歧义、资产已删或数量超限均返回 `reference_issues`，不猜图、不截断、不用其他造型填缺口。
- 手动选择保留顺序，按资产／造型 ID 更新图片地址。组设置提供“恢复自动关联”。拆分后的自动组继续自动关联。
- 参考变化保留提示词正文，但现有指纹检查使其变为待更新；旧候选不能直接采纳，需重新生成。写词缺图在任务入队前阻断；整批写词全部失败记录为失败。
- 计划返回 `reference_fingerprint`。新前端提交 `expected_reference_fingerprint`，后端在保存、采纳、写词和视频任务创建检查资产快照；编辑框及组弹窗保留开始编辑时的快照，防止轮询更新掩盖冲突。
- 界面显示具体组和缺失资产；资产库提示缺图造型数量，批量生成有跳过项时不宣称全部就绪。候选稿在编辑器上方展示并显式采纳。

## 兼容与文件

无数据库表迁移。旧空参考组默认自动；旧非空参考组默认手动，以保留历史选择。旧客户端未传参考快照字段仍可调用，但保留原版本／提示词指纹校验；新前端提供额外并发保护。真正尚未生成的资产仍需在资产库补图，完成后自动关联，不会凭空生成图片。

后端：`workshop_references.py`、`workshop_service.py`、`workshop_contract.py`、`project_detail_service.py`、`episode_video_service.py`。前端：`workshop-api.ts`、`UnifiedWorkshopPane.tsx`、`AssetsLibraryPane.tsx`、`JobsCenterPane.tsx`、`workshop-references.ts`。测试：`backend/tests/test_workshop_reference_lifecycle.py`、`backend/tests/test_workshop_video_preflight.py`、前端参考阻断摘要测试。

最终结果：上述后端回归 265 项通过；前端 63 个测试文件、306 项通过，TypeScript 和生产构建通过。5173 浅色／暗色工坊均显示具体缺图资产，组弹窗显示自动关联状态；资产库显示实际缺图造型数。截图基线位于 `docs/design-ref-director/2026-09-25-workshop-reference-light.png`、`2026-09-25-workshop-reference-dark.png`、`2026-09-25-assets-missing-looks.png`。

回滚仅撤回上述文件中本修复增量及文档，保留工作区其他功能；已保存正文、候选与资产不删除。新增 JSON 字段为兼容性元数据；撤回解析器后恢复旧手工参考行为。
