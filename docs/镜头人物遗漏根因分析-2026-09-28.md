# 镜头人物遗漏根因分析

日期：2026-09-28。性质：实际数据与当前代码调查，尚未实施修复。

## 结论

本次不是剧本扩写漏写男主。扩写任务和采纳剧本都明确保留了沈砚与母亲。最早能观察到的错误位于内容库的出片镜头规划结果：第 8 镜的人物数组只有母亲，而动作及收束明确描述沈砚坐起身。工坊复用该镜头，资产关联按不完整的人物数组执行，最终写稿只获得母亲的身份参考。

系统性原因是镜头规划没有建立“本镜出镜人物与最终画面描述一致”的校验，衔接修订可以更改画面却不能更新人物数组，后续关联也没有发现这个矛盾。不能仅通过补当前镜头素材或增加一句提示词宣称根治。

## 代码中的放行点

1. `episode_shot_planner.py::build_shot_plan_system_prompt` 要求输出 `characters`，但原有规则没有明确要求核对静默人物、被看者和开场/落幅才出现的人物。`normalize_planned_shots` / `_blank_shot` 保留模型给出的列表，不从动作核实人物。
2. `llm_service.py::plan_episode_shots` 检查非空结果和对白覆盖；通过后进入衔接修订。没有画面人物完整性检查。
3. `episode_shot_planner.py::build_shot_continuity_refine_system_prompt` 明确禁止改 `characters`。`CONTINUITY_EDITABLE_FIELDS` 和 `apply_continuity_window_revision` 只更新动作、画面描述、开场、收束和转场。因此修订可以使人物进入动作/落幅，却不能同步人物数组；修订后也无一致性复核。
4. `project_detail_service.py::_beats_from_document_shots` 使用 `shot.characters` 匹配人物资产，不依据剧情重新判断出镜者。
5. `workshop_service.py::run` 在 `reuse_existing=true` 时复制旧 beats；`workshop_references.py::resolve_state` 按人物列表和已有 ID 填充参考。只要母亲图可用，就不会因男主遗漏而报错。
6. `workshop_direct_input.py::build_input` 虽发送完整剧本和镜头动作，但实际视频参考只有母亲；当前执行检查不会检查每个应出镜角色是否有独立且正确的身份参考。

## 能确定与尚不能确定的边界

能确定：扩写原稿正确；错误在进入工坊前已存在；规划链路缺少一致性检查；后续按错误列表传递。

尚不能区分：拆镜模型初稿就同时写了沈砚动作却漏人物列表，还是初稿只拍母亲、衔接修订随后将沈砚加入画面。所检查的历史规划任务只存汇总，没有保留这两次调用的逐次原文。当前代码说明后者有机制风险，但不能据此声称它就是这一次的已证实原因。

本次未重新播放或重新生成视频；“儿子使用母亲外观”来自用户反馈。已验证的不完整参考和身份定义与该反馈相符，但不将其表述为本轮成片验收结果。

## 同类风险

第 23 镜「望向农田」人物数组只有沈砚，开场却写“站在里屋，神情坚定地看着母亲”。这是另一处需要语义核对的候选：看着某人不一定意味着对方入画，不能看到名字就自动补参考。人物盘点应区分实际可见、画外发声、对白提及、回忆未呈现，以及画面中尚未明确的角色。

## 完整修复方案（待实施）

1. **明确镜头规划的人物合同**：人物列表覆盖全镜头时段，包含静默听者、互动对象和起止帧可见人物；明确区分画外人物及只被提及的人物。不要将全场演员无差别复制到每个镜头。
2. **在最终衔接修订之后核对人物**：以原场景、最终动作、机位和开场/收束共同判定出镜者，输出人物与原文证据。可只修人物归属，不改剧情、对白和镜数。矛盾要反馈修订或显式待确认，不静默接受；不能仅靠姓名子串正则判定出镜。
3. **保留每阶段证据**：保存拆镜初稿、衔接修订结果和人物核对结果及来源版本，使下一次能直接定位哪一步造成不一致。
4. **统一新规划与旧镜头复用入口**：内容库规划、工坊重新规划及旧镜头复用都应使用同一核对规则。原始人物名单与已确认人工绑定区分保存，人工改动不能被自动覆盖。
5. **写稿/出片前检查对应关系**：已确认出镜人物应映射到正确资产和时代造型；无参考或用户刻意采用无图人物需明确表达，不能默用另一个角色的图。角色或参考变更后，已有提示词按现有指纹失效并保留历史，需重新确认稿件。
6. **回归范围**：本例的母子双人镜；衔接修订新增可见角色；静默人物；画外声音；对白只提及第三人；只露背影/手部；人物别名与重名；现代/古代造型；人工排除；参考上限；旧镜头复用；参考变更导致旧候选不可采纳。

既有项目修复应在上述机制确定后进行：保留旧数据和提示词，修正已确认遗漏的第 8 镜，核对其他疑点，再生成/审阅该组新稿。已有视频不会因修改参考自动修复。
