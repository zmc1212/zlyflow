# 视频任务重启恢复（2026-09-29）

## 原因和现场

项目 `proj-f5a791c91ebe468f`，任务 `job-de6d227d1033` 于 09:34 提交，09:47:54 被启动恢复逻辑标成“服务进程重启，后台视频任务已中断，请点击重试”。实际配置是远端 `http://192.168.10.54:8188`，原 prompt `7344676e-f86d-4936-af88-709b2073de19` 仍在运行队列。原实现仅按本地状态批量置失败，没有远端对账。

## 实现和边界

- `episode_video_service.py`：按原 prompt 重连；普通视频也使用领取 CAS、120 秒租约与 30 秒心跳；本进程防重复调度；MySQL 幂等写入的 affected rows 为 0 时再次核对 owner，避免误报租约转移。
- `video_recovery.py`：只读查询冻结远端实例的 history/queue，并再读 history 处理完成竞争；旧任务从已保存 graph、prompt 和已完成分段输出恢复检查点，缺失证据拒绝推测。
- `comfy_checkpoints` 保存逐段提交前意图、graph、回执与输出。恢复已提交段仅等待原 prompt，已完成段复用输出；后续尚未提交段按原任务继续。冻结镜头不重新调用模型或上传参考图。确认工作流保留原有专用检查点和校验。
- `main.py`：生命周期内每 30 秒扫描过期租约，退出取消扫描。短暂网络中断保留活动状态，不把网络不可达等同于远端失败。
- “重试”在远端原任务仍活动或已完成时改为重连接回。真正失败或记录丢失保留原错误；正常显式重新生成沿用原入口。
- 提交已发生但回执尚未落盘时不能保证找回 prompt；此时停止并提示核对，绝不自动再 POST。独立合成/超分没有完整远端检查点时仍按证据不足处理，未宣称通用恢复所有 GPU 操作。
- 无数据库 DDL、API 路径、端口、供应商、节点 ID 或模型变更。增量兼容已有任务 JSON，不删除旧结果。
