# 大模型视觉能力路由彻底修复开发计划

日期：2026-09-26
状态：核心实现、自动化回归及设置页桌面双主题检查已完成；真实业务写稿/出片验收未执行。VLM 完整复用的最终契约和验证边界见第 9 节。
目标：把“模型能否看图”从按名字猜，改为可探测、可持久化、可追溯的能力数据；写稿与分析路径按真实能力路由，跨供应商凭据不再拼出错误组合，带图失败不再被静默掩盖成文本成功。

## 1. 已确认的根因

### 1.1 能力判定只靠硬编码名字名单

`backend/app/llm_provider.py:29` 的 `VISION_MODEL_MARKERS` 用字符串包含关系判断 `model_supports_vision()`。`deepseek-v4.1-flash` 不含 `vl` / `vision` / `qwen-vl` 等标记，被误判为“不可看图”，尽管实测它能正确识别红色与蓝色测试图。

同一份名字判断被分散在多处重复使用，规则各自演进：

- `backend/app/vision_runtime.py:104/122/221/228/252`：写稿与分析的公开路由和 endpoint 解析。
- `backend/app/llm_provider.py:111`：LLM 状态里的 `supports_vision`。
- `backend/app/vlm_provider.py:88/148/187/232`：VLM 可用性校验、保存校验、测试校验、目录过滤。
- `backend/app/media_studio/services/llm_service.py:146`：带图写稿前置判断。

### 1.2 “复用大模型凭据”拼出跨供应商组合

`backend/app/vision_runtime.py:50` 的 `overlay_vlm_credentials()` 只覆盖 VLM 行的 `base_url` 与 API Key，不覆盖模型名。当前配置产生：阿里云 MaaS 地址 + 阿里云 Key + `glm-4v-flash`，实测上游返回 `Model not exist`（HTTP 404）。该组合在保存和测试时没有校验。

### 1.3 带图失败后静默降级为无图文本，且元数据被丢弃

`backend/app/vision_runtime.py:379` 的 `complete_authoring()` 在带图调用失败后进入 `VISION_STATUS_FAILED_TEXT_FALLBACK`，用同一模型不带图重试，任务仍可能显示成功。实测生产路径得到 `status=failed_text_fallback`、`source=vlm`、`model=glm-4v-flash`、`images=1`——真实行为是“DeepSeek 不带参考图写稿”，但记录的模型名是 GLM，掩盖了参考图从未参与的事实。

`backend/app/media_studio/services/workshop_group_prompts.py:48` 调用 `chat_vision()` 后只取返回文本，丢弃 `VisionCallMeta`，导致工坊任务没有保存实际路由证据。

### 1.4 连接测试只验证文本，不验证视觉

`backend/app/llm_client.py:1267` 的 `test_connection()` 是纯文本最小调用；即使把 DeepSeek 加进名字名单，当前“测试成功”也不能证明它真的能收图。`/models` 目录（`llm_client.py:798`）也不足为凭，智谱等供应商的 VL 模型常不在目录里。

## 2. 目标架构

```text
配置保存 / 测试连接
        │
        ├─ 文本连通探测（现有）
        └─ 视觉能力探测（新增：小图最小请求，可选语义校验）
                    │
                    ▼
        持久化视觉能力：unknown / supported / unsupported
            + 校验时间 + 校验方式 + 上游结果（不存密钥）
                    │
                    ▼
        统一路由解析器 resolve_*_endpoint(llm, vlm, capabilities)
            ├─ 校验“复用凭据”组合合法（同一供应商能力内）
            ├─ 选出真实可用的 endpoint 与决策原因
            └─ 失败策略显式化：不满足时不静默降级
                    │
                    ▼
        调用返回 VisionCallMeta（requested / actual / status / fallback / request id）
                    │
                    ▼
        任务与设置页可查询、可展示真实路由
```

设计要点：

- 视觉能力绑定 `(profile, base_url, model, credential fingerprint)`，不是全局模型名属性；同名模型在不同网关或凭据下不得共享证据。
- “复用大模型连接”最终定义为完整跟随 LLM 的地址、密钥、模型、profile 及验证证据，不在 VLM 页另选模型；独立配置保留，关闭复用后恢复。这取代初版“只借地址与密钥、另选 VLM 模型”的方案。
- 写稿路径的视觉要求是显式契约：需要参考图时，必须选中一个已验证支持的带图 endpoint。没有可用带图 endpoint 时，任务按配置的失败策略处理（阻断或明确告警），禁止不告知用户就改成无图生成并显示成功。
- 分析路径（资产反推、拉片）优先 VLM；VLM 不可用且 LLM 已验证支持视觉时才用 LLM，与现有语义一致，但改用持久化能力判断。

## 3. 实施阶段

### P0 基线归档

- 保留当前名字名单及其命中结果，作为回滚与迁移初值依据。
- 记录本轮实测证据：DeepSeek 双色图测试正确、阿里云地址下 `glm-4v-flash` 返回 404、生产路径 `failed_text_fallback` 的元数据形态。
- 不修改供应商配置，不做真实写稿，避免影响当前任务。

### P1 视觉能力探测与持久化

- 新增能力探测函数：用最小合法图片（如 1×1 或单色图）发一次带图最小请求；可选项为双色语义校验，验证模型不是“忽略图片也能答对”。超时短、token 极小。
- 新增存储字段（SQLite 与远程 MySQL 同步迁移）：

```text
vision_capability            unknown | supported | unsupported
vision_capability_source     probe | catalog | legacy_name_guess | manual
vision_capability_checked_at
vision_capability_message    （上游错误摘要，不含密钥）
```

- 历史数据以 `legacy_name_guess` 标识名称推断，但有效能力仍为 unknown，不授权图片；需真实探测后升级。
- 扩展 LLM/VLM 的“测试连接”：文本测试成功后追加视觉探测，把结果写回上述字段；失败仅记录 `unsupported` 与原因，不阻塞文本模型保存。
- 探测结果缓存有效期内复用；配置（URL/模型/Key 指纹）变化后标记为 unknown，下次使用时重新探测或要求用户测试。

### P2 统一路由解析器

- 收敛 `llm_provider.py` / `vlm_provider.py` / `vision_runtime.py` / `llm_service.py` 中的分散判断到单一能力读取入口，`model_supports_vision()` 降级为历史兼容别名或直接删除。
- `resolve_authoring_endpoint` / `resolve_analysis_endpoint` 改为接收能力数据：

  - LLM 能力为 `supported` 时，写稿直接带图调用 LLM。
  - LLM 能力为 `unknown` 时，先做一次短探测再决定；探测失败才走 VLM。
  - 复用凭据生效时，先校验组合在当前供应商能力下可用；不可用直接报出“模型与地址不匹配”，不进入调用。
- 路由结果携带决策原因，便于任务展示和排障。

### P3 失败策略显式化与元数据贯穿

- `complete_authoring()` 增加失败策略参数：`block`（阻断并报错）、`warn_and_text`（明确标记降级）。默认写稿路径使用 `block`；确需文本回退的场景显式传入并记录。
- 移除“带图失败自动改无图重试后显示成功”的静默行为：无图回退必须反映在任务状态、错误信息或警告字段中。
- `chat_vision()` 返回 `VisionCallMeta`；`workshop_group_prompts.py` 与 `workshop_service.py` 把 `requested_model`、`actual_model`、`status`、`fallback`、`request_id` 写入任务 payload 快照，历史任务不重写。
- 修正失败回退时记录“实际模型”，不再把 `glm-4v-flash` 当成实际作者写入 meta。

### P4 设置页与工坊可见性

- 管理设置 LLM / VLM 页展示视觉能力三态与校验时间，提供“重新探测视觉能力”按钮；`supports_vision` 文案改为真实验证结果，名字猜测仅作为未验证时的提示。
- “复用大模型连接”说明完整跟随 LLM，禁用独立模型输入/目录，共享已验证结果与探测时间；未保存切换明确标记预览。
- 工坊任务与候选区显示本次实际写稿模型、是否带图、是否发生降级；失败降级不再呈现为普通成功。

### P5 测试与回归

单元测试覆盖：

- 能力三态与迁移回填；配置变化使缓存失效。
- 统一解析器各分支：LLM 支持 / unknown / 不支持；VLM 优先与回退；复用凭据组合合法与跨供应商拒绝。
- 失败策略：`block` 不静默降级；`warn_and_text` 必须记录降级。
- 元数据贯穿：workshop 任务 payload 保存 requested/actual/status/fallback。
- 探测函数用 mock 上游，不依赖网络；真实探测作为手动验收步骤。

回归基线：

```powershell
python -m unittest discover -s backend/tests -p "test_llm*.py"
python -m unittest discover -s backend/tests -p "test_workshop*.py"
python -m unittest backend.tests.media_studio_test_h3_video -q
pnpm --dir frontend build
```

实施时按实际测试模块名补充，记录真实通过数量，不使用此前结果代替本轮结果。

## 4. 数据迁移与兼容

- MySQL 与 profile 表采用增量加列，不重建或清空表；正常代码回滚保留列与证据，不以删列作为常规回滚手段。
- SQLite 本地迁移同样加列，unittest 使用临时库时自动建新列。
- 旧任务继续绑定创建时的快照；回填的 `legacy_name_guess` 只用于旧数据初次显示，不冒充探测结果。
- 视觉探测与写稿路径相互隔离：探测超时或上游异常只影响能力字段，不阻塞文本写稿。

## 5. 验收标准

- 当前配置下，`deepseek-v4.1-flash` 探测结果为 `supported`，来源为 `probe`；带参考图的工坊写稿实际调用 DeepSeek，任务元数据显示 `source=llm`、`status=used`、模型名正确。
- 勾选“复用大模型连接”后，LLM / VLM 显示并调用同一模型与证据，不再出现 `glm-4v-flash` + LLM 地址的混搭；已有有效验证无需重复探测。
- 带图写稿失败时，任务失败或明确标注降级，绝不无提示地显示为正常成功；实际作者模型可查。
- 管理设置与工坊页面能看到真实视觉能力状态与实际路由。
- 后端相关测试全绿、前端构建通过、5173 桌面双主题检查通过；不主动做移动端检查。

## 9. 本轮实施与验收记录（2026-09-26）

### 用户反馈后的最终契约

LLM 已验证可看图，而 VLM 开启复用仍显示旧 GLM。根因是旧 overlay 只替换地址和密钥，模型与能力仍来自独立 VLM。最终实现完整复用 LLM 的模型、profile、连接及验证证据；已有有效能力不重复探测，独立 GLM 配置和凭据不覆盖，关闭复用恢复。保存过程中 LLM 改动会拒绝旧结果；空 JSON 测试请求继承已保存复用状态。

前端同时刷新 LLM/VLM 查询缓存，含失败探测路径；复用模式不自动拉独立模型目录，隐藏独立预设并禁用模型编辑；LLM 页不再按模型名显示“不能看图”。两页的当前模型、状态、探测时间与错误说明一致。

### 实页及数据安全边界

5173 管理页桌面 1440×900 浅/暗主题已截图检查：LLM / VLM 同显 deepseek-v4.1-flash、“已验证可看图”和相同验证时间；LLM 不再出现模型名称不能看图的矛盾提示。关闭再开启复用的未保存表单预览会恢复独立 GLM、再切回 LLM，最后恢复原开关、浅色主题与默认视口。页面停留在 VLM 设置供用户查看。后端由既有 dev_reloader 自动加载代码，没有另起 ComfyUI。

没有保存/改动用户的供应商 URL、Key 或模型，未再次调用收费探测，未执行真实写稿、资产反推或视频生成。能力来源是用户已经完成并持久化的双色图验证；不是本轮另一次真实上游验证。工坊降级证据已通过组件测试，真实工坊任务与出片仍待用户业务验证；会话截图已检查，磁盘参考截图未归档。
