# 阿里云写稿参考图下载超时修复

日期：2026-09-27（本机北京时间）。

## 原因与历史证据

- 原失败任务 `job-0477663ee346`：第一组 3 镜，指定 `deepseek-v4.1-flash`，4 张有序参考图。阿里云 MaaS 返回 HTTP 400，SSE 错误为 `Download multimodal file timed out`，原请求 ID 为 `chatcmpl-4f21818d-cf4f-9dce-b2bd-3620c8014aa0`。
- 四张 PNG 合计 6,039,638 字节，本机逐张 GET 均为 200，约 0.28–0.30 秒。该结果只证明本机到 CDN 可达，不能证明阿里云内部下载链路可达。
- 视觉能力验证使用内嵌 Base64 双色小图；此前业务调用直接传外链 URL。两条传输路径不同，所以能力探测通过仍可能业务拉图超时。
- 更直接的历史证据：同一失败任务的首轮外链调用其实已成功，实际响应模型为 `deepseek-v4.1-flash`，`image_tokens=3780`，请求 ID `chatcmpl-65495a3d-ed05-924d-8c44-0af96639477f`；第二轮结构返修才发生下载超时。因此问题是上游拉取外链的间歇性失败，不是 DeepSeek 不支持图片，也不能把历史成功一概归因为旧回退。
- 已核对 2026-09-26 的成功任务，包括 `job-189fc1c1200d`、`job-5ee4d08ab163`（均有 4 张参考）。旧任务没有保存实际写稿模型或逐轮调用证据，不能声称它们一定是 DeepSeek 真正看图后完成。旧基线 `bd6ebbc` 的 `vision_runtime.resolve_authoring_endpoint/complete_authoring` 按模型名选择 LLM/VLM，视觉失败后可纯文本回退；当前基线明确指定作者并禁止静默丢图，暴露了以前不一定被报告的传输失败。无证据证明 CDN 一直不可用，也不把问题归为 DeepSeek 不支持图片。

## 修复范围

- 新增 `backend/app/llm_image_transport.py`：仅为官方 DashScope 域名和 `*.maas.aliyuncs.com` 端点将 `image_url` 转为内嵌 Base64；不按模型名猜能力，其他供应商和纯文本请求不变。
- 图片在后端通过独立、无模型凭据和无 `.netrc` 的会话下载；校验 HTTP(S)、DNS 公网地址、逐跳重定向、MIME、文件可解码性、20 MiB 原文件与 4000 万像素上限。
- 本机代理把媒体域名解析到 `198.18.0.0/15` 和 `fdfe:dcba:9876::/48`。例外仅限管理员七牛设置的精确 HTTPS 域名及 443 端口；非配置域名、实际内网/回环/链路本地地址仍拒绝；配置读取失败时拒绝。
- 每次请求保持所有参考图的位置、重复槽位、文本与 `detail`；重复 URL 仅下载一次，不合并 Picture 槽位。原图、原 URL、任务快照和模型选择均不改变。
- 超限时只压缩传输副本，最长边 2048，单图编码前最多 2 MiB，并按图片数量分配总计 8 MiB 的 Base64 预算；保留透明通道。小图/合规原图保留原始字节，已有 Base64 不重复编码。
- 任一图片失败则在提交模型前明确指出第几张失败；不丢图、不改用 VLM、不回退纯文本，不自动重复收费请求。
- `llm_client.py` 接入共享传输；`media_studio/services/llm_service.py` 在作者证据中保留 `image_transport`、图片数量、传输字节数及准备失败阶段，不保存图片数据、签名 URL 或 Key。
- 完整任务暴露出提示与校验不一致：系统曾允许尾段只写“停顿或承接姿态”，审稿要求明确闭口/静默。`workshop_h3_skill.py` 对齐这条要求，`workshop_group_prompts.py` 在原始输入旁补充逐镜原文核对、同一对白窗的声音归属、无对白镜不带 S 编号和独立静默尾段要求。该补充也作用于旧任务重试，但不改写旧合同快照、原剧情、模型输出或既有质量校验。
- `.gitignore` 为两份正式回归测试增加白名单，避免它们被原有 `backend/tests/test_*.py` 规则忽略。
