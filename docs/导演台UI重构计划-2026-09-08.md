# 导演台 UI 重构计划

日期：2026-09-08。状态：待实施；本次仅分析代码和检查页面，未修改业务代码。

## 1. 结论与目标

本次以用户明确选择的“全流程引导”为优先目标。导演台已具备剧本、资产版本、分镜、生成、声音和交付能力，但当前界面把阶段导航、工作视图和执行操作交织在一起。重构重点是让创作者随时知道：当前产物是什么、哪些内容可用、还缺什么、下一步在哪里。

采用五阶段创作导航：**故事与风格 → 分镜设计 → 视觉素材 → 镜头制作 → 声音与交付**。允许任意回访和手动导入，不强制从第一步开始。保留剪辑视图，作为用户主动进入的进阶工作面。

成功标准：已有分镜的工程能直接继续制作；失败镜头能从状态提示直接定位并重试；没有生成结果时能看到修复入口；手机首屏能看到当前阶段的核心内容；浏览页面不会启动生成或导出。

## 2. 审查范围与证据

已阅读项目规则、README、功能指南与架构快照，并检查导演台主组件、阶段导航、readiness、资产卡、镜头 Inspector、导出面板、保存/冲突处理及相关测试入口。以当前工作区为准，已有未提交的手动分镜导入、对白及工作流修改必须保留。

实际页面检查：指定工程登录后，在 1440×900 检查分镜设计、角色定妆和成片；在 390×844 检查分镜设计。只操作登录、导航、视口和截图，未主动点击生成、批准或导出。工程内容在检查期间存在异步变化，跨截图的总时长与状态差异不直接认定为确定缺陷。

### 2.1 分镜设计

![桌面分镜页](../output/playwright/director-before-desktop.png)

- **P0：浏览可能触发生成。** `DirectorRecipeStudio.tsx` 的 `handleStageChange` 和分镜阶段 effect 调用 `handleGenerateStoryboard`；后者有条件保护，但空白/占位分镜满足条件时仍可能创建操作。必须移除导航带来的生成副作用。
- **P1：阶段和工作方式混淆。** 桌面选择 `shots` 会切换 `view=timeline`；进入一个流程步骤同时改变整个布局，移动端又使用另一行为。
- **P1：分镜设计承担过多制作动作。** 页头有整批预览/终稿，右侧有静帧、单镜视频、配音；用户需要先理解多种生成机制，才能专注分镜内容。
- **P1：状态含义不一致。** 同一截图中镜头卡为“待生成”，Take 为“失败”；阶段的“已就绪”并不能说明可以直接出片。readiness 主要看内容存在性，角色/场景又以 `imageUrl` 计数，不能完整表达版本批准与运行状态。
- **P1：空预览占据大量面积。** 缺少结果时中心区域几乎空白，没有说明缺少什么、推荐动作和失败恢复路径。
- **P2：术语和无障碍。** “模型体积”、MP、步数等技术信息处于主表单；顶栏有无可访问名称的图标按钮，截图中部分显示为空框，需核查图标渲染及样式覆盖。

### 2.2 角色资产

![角色资产页](../output/playwright/director-before-assets.png)

- **P1：完成后没有衔接。** 当前角色已批准，页面仍突出“全部定妆”，没有引导使用该资产制作镜头。
- **P2：层级解释不足。** “肖像 / 定妆板 / 候选 / 批准 / 入库”的关系需要用户自行理解；已有批准素材时仍需要明确区分“查看”“重新生成”和“投入镜头”。

### 2.3 手机分镜页

![手机分镜页](../output/playwright/director-before-mobile.png)

- **P1：参数挤占首屏。** 输出设置占到约 540px，核心镜头列表在下方才出现；生成速度和分辨率禁用后仍占用显著空间。
- **P1：列表宽度利用不足。** 可见镜头区域很窄，右侧留白，卡片标题被截断；桌面多列结构需要真正改为手机单列流程。
- **P2：底部动作缺少上下文。** 固定“全部预览”没有同时解释选中范围、缺项或失败项。

### 2.4 成片

![成片页](../output/playwright/director-before-export.png)

- **P1：禁用后没有恢复入口。** “可进入成片 0 / 4”下面整排按钮禁用，未提供“查看未完成镜头”。
- **P2：信息顺序倒置。** ffmpeg 路径和字幕样式先于成片预览、缺项清单及主操作；字幕相关开关分布在两处，容易产生理解成本。

限制：本次未实测真实生成、收费、批准、导出、断网恢复及跨设备编辑；暗色主题、剪辑播放和完整键盘操作列入实施回归。截图不能证明这些能力正常或失效。

## 3. 页面与交互方案

### 3.1 导航和共同框架

- 顶部仅保留工程库、可编辑项目名、明确的保存状态、任务活动入口、主题及更多菜单。创意简报移至“故事与风格”，其他阶段仅保留可展开摘要。
- 左侧固定五阶段导航，显示阶段名称、产物计数和待处理数量。每阶段顶部展示一句任务目标、当前缺项及一个主动作；次要动作进入更多菜单。
- 默认导航顺序为故事与风格（剧本、画风）、分镜设计、视觉素材（角色、场景、道具）、镜头制作、声音与交付（配音、配乐、成片）。此顺序是推荐工作路径，不构成强制依赖。
- “继续下一步”只导航；“生成分镜”“生成选中镜头”“导出成片”明确执行。重新生成可能覆盖内容时显示影响范围确认；普通导航和可逆编辑不增加确认。
- 剪辑入口置于镜头制作和交付页面，点击才进入，保留原选中镜头；返回创作流程恢复阶段、选中镜头和滚动位置。

### 3.2 各阶段默认内容

| 阶段 | 主内容 | 主动作与完成后的衔接 |
| --- | --- | --- |
| 故事与风格 | 创意、剧本、画风；支持已有内容 | 明确生成范围的“生成创作方案”；有剧本后“前往分镜设计” |
| 分镜设计 | 按场景排序的镜头列表、时长、描述、对白及角色/场景关联 | 空白时“生成分镜”，并列“导入分镜”；已有内容时“前往视觉素材” |
| 视觉素材 | 角色/场景/道具页签，候选和已采用版本 | 显示当前资产下一动作；完成或无需素材时“前往镜头制作” |
| 镜头制作 | 镜头列表、媒体预览、生成与版本选择 | “生成待处理镜头（N）”；选中后变为“生成选中（N）” |
| 声音与交付 | 配音、配乐、成片页签；成片先显示预览与检查清单 | 缺视频时“查看未完成镜头”；满足条件时“导出成片” |

- 分镜设计与镜头制作共用镜头数据和编辑组件，默认呈现不同关注点，不复制 Recipe。手动导入/重新导入保留，重新导入前明确替换范围与已有媒体影响。
- 镜头制作桌面采用 200px 镜头列表、弹性预览、360px 详情区；小于 1200px 时详情转 Drawer，小于 768px 改单列。空媒体显示镜头摘要、状态、失败原因摘要及下一动作，不保留巨大的无说明空白。
- 分镜详情默认显示创作内容；镜头语言、关联素材、对白按任务分组。静帧和视频生成移至制作区域，配音主入口移至声音区域，保留必要的跨阶段快捷跳转。
- 多选工具栏仅在选择后出现，明确范围与数量；保留失败重试、停止选中。重新生成成功镜头放入显式次操作，避免“全部”误覆盖。
- 资产卡用“生成肖像 → 采用肖像 → 生成定妆 → 采用定妆”表达关系；底层仍使用批准协议。已批准资产默认查看/继续，重新生成是次操作。入库不作为继续制作的前提。
- 成片页先显示可用/缺失镜头及定位链接，再提供主导出动作。允许沿用后端现有部分成片能力，但必须明确展示将排除的镜头并由用户选择“仅导出可用镜头”；不静默忽略。字幕关闭时收起样式，ffmpeg 路径移至运行详情。

### 3.3 参数、状态和保存

- 常用参数只显示用户可理解的生成目标、画面比例和质量摘要；高级项放“更多设置”。模型体积、步数、内部路由默认隐藏，完整快照保留于运行参数。
- 参数展示及约束使用 `/api/modes` 的注册表元数据；所需导演语义预设在后端声明映射，不能在前端另建按参数名判断的显示清单。预览模式摘要必须反映实际有效值，而不是禁用的终稿值。
- 内容准备度、运行状态、媒体采用状态分别表达：例如“分镜已设计 · 视频失败 · 未采用版本”。不把失败、未生成、未批准合并成一个标签。
- 阶段评估补充缺项原因和跳转目标；无对白显示“无需配音”，无强制参考素材的文生镜头不被定妆门禁阻塞。缺项按选定工作流能力和当前镜头引用评估，后端提交校验仍为最终依据。
- 下一步规则：优先当前阶段的可执行工作；无法执行时显示第一个真实阻塞项及定位入口；当前阶段已满足时提供推荐下一阶段。生成运行中可继续浏览，轮询不得覆盖未保存输入。
- 保留现有自动保存、revision/content_revision 冲突检测和恢复机制。顶栏区分“保存中 / 已保存 / 保存失败 / 存在冲突”；提交前等待保存成功，失败时保留草稿并提供重试。冲突解决保留当前已有选择，不做自动覆盖。

### 3.4 视觉与手机

- 沿用 Ant Design、根级主题 Provider 和 `--studio-*`，不新增同功能 UI 封装或设计系统。浅色默认，暗色共用语义 token，弹层继承主题。
- 1440×900 下标题、关键状态和主动作首屏可见；减少层层卡片和重复标题。正常文字目标对比度 4.5:1，状态附文字，所有图标按钮具备可访问名称与键盘焦点。
- 390×844 下阶段摘要之后直接显示核心内容；参数进入 Drawer，以一行摘要作为入口。底部只固定当前上下文主动作，预留安全区和内容底部间距。触控目标至少 44px，表单、卡片不横向溢出。

## 4. 实施拆分与兼容

按以下顺序交付，每步都保持工程可打开：

1. **P0：动作与状态。** 移除导航自动生成、顶部导出导航立即 mux 的耦合；补充阶段缺项及镜头状态派生测试。统一桌面/手机的动作定义。
2. **P1：流程骨架。** 建立五阶段分组、阶段主动作、缺项定位、项目保存状态和任务入口。保留现有路由语义，再调整页面可见标签。
3. **P1：工作面。** 拆分分镜设计/镜头制作默认呈现；整理资产采用流程与交付检查清单；修复手机宽度和首屏顺序。
4. **P2：视觉与回归。** 完成双主题、图标、键盘、空态和错误态检查，同步文档后交付。

代码组织：从当前约 2906 行的 `frontend/src/director/DirectorRecipeStudio.tsx` 提取项目会话与保存 hook、操作/任务 hook、阶段流程纯函数和阶段业务区域；主组件保留组装与路由职责。复用已有 project/operation controller，避免同时维护新旧两套保存或轮询逻辑。

接口边界：保留所有既有 `stage` 值、`view=plan|timeline`、旧 stage 别名及工程 ID；新五阶段仅为导航分组。保留 Recipe、资产版本、Take 与后端工作流节点协议，不迁移数据库。前端新增统一阶段评估结果（完成度、缺项、推荐动作）和动作描述供桌面/手机共同消费；工作流元数据如需补充，仅对现有响应做兼容扩展。

涉及状态模型和用户行为变化，实施时同步更新 `docs/ARCHITECTURE.md`、`功能说明与扩展指南.md`、`README.md`，记录日期、原因、受影响模块、兼容性、验证与回滚。按独立提交回滚本次新增变更；不重置或覆盖用户已有未提交工作。工作台部署端口仍为 7865，本次 5173 仅用于现有开发页面核查。

## 5. 验收与风险

- 路由：九个现有 stage 深链接、旧别名、前进后退及手机/桌面切换可用；打开或切换阶段、剪辑视图均不发送生成/导出请求。
- 流程：空工程、只有手动分镜、无角色文生、已有已采用素材、无对白、部分失败、全部完成均显示合理下一步；导入工程不强制补写剧本才能制作。
- 状态：失败 Take、生成中、多个候选、旧批准版本与新失败版本共存时，卡片/详情/阶段/导出采用口径一致；重试仅作用于明确范围。
- 保存：快速输入后切换阶段、生成前保存失败、远程冲突、刷新恢复任务不丢输入、不重复提交；沿用现有 controller 测试并扩展实际边界。
- 参数：验证 primary/advanced/internal、预设默认值、后端 graph 映射和任务有效参数回显；前端隐藏不改变历史参数含义。
- 视觉：1440×900、1280×800、390×844，浅色/暗色；检查 Drawer、Select、Modal、固定底栏、长标题、空媒体、错误提示与键盘导航。
- 自动检查：`pnpm --dir frontend build`（包含 Vitest 与 TypeScript）；`python -m pytest backend/tests -q`。本次计划阶段未运行构建或后端测试，不能视为已通过。
- 主要风险：主组件拆分触及自动保存和轮询；已有工作流/手动导入改动并行存在；真实工程数据可能持续更新。实施前重新核对 diff，测试使用独立固定样本，不以正在变化的生产项目作断言基准。

默认边界：本轮覆盖现有导演工程创作流程与响应式界面；工程库只统一继续创作入口，不重构管理后台、导台2、模型服务或专业剪辑引擎。新的视觉布局基于现有组件与品牌，先完成流程和信息层级，再做细节打磨。
