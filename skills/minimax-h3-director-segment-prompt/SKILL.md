# MiniMax H3 Director 连续分段提示词

## 目标

把来源分镜改写成 MiniMax H3 Director 能执行的连续画面提示词，同时保留原剧本事实、对白和镜头意图。输出既要有 H3 的主体/声音/动作写法，也要有 Director 的事件单次分配、状态交接和独立分段时间规则。

## 规则优先级

**MiniMax H3 格式是主格式，Director 规则是约束层。** 必须先保证 `subject_definitions`、声音设定、`<d>[中文]台词</d>`、动作带语气和【约束】等 H3 写法完整，再把 Director 的时间、事件、对白归属和交接状态嵌入其中。

- Director 规则不得替换 H3 的主体定义、声音标记、台词格式或动作表演写法。
- Director 规则与 H3 表演写法冲突时，保留 H3 的声画表达，只调整时间码、状态承接和事件边界。
- 不输出纯 Director JSON、旧版 `=====` 分隔文本或只有事件清单的提示词；最终交付必须仍是可直接给 MiniMax H3 使用的完整提示词。

## 适用边界

- 目标必须是 MiniMax H3 Director；不是 H3 时停止，不改写成其他模型的通用提示词。
- 适用于工作台按 Director segment 提交到 ComfyUI 的视频，也适用于一个 segment 内包含多个 `[Shot N]` 的连续提示词。
- 不使用旧版 `===== 公共设定 =====`、`===== 提示词组 k =====` 分隔格式；工作台保存和提交使用当前结构化协议。

## 最重要的时间规则

先判断提示词的提交边界：

### A. 一个 segment 内包含多个镜头

该 segment 的时间从 `0秒` 开始，segment 内的 `[Shot N]` 可以连续累计，例如 `0–4秒`、`4–8秒`。累计只在这个 segment 内有效。

### B. 每个镜头作为独立 segment 提交

每个 segment 的提示词时间必须从 `0秒` 开始，例如两个 8 秒 segment 都写成 `0–8秒`。不要把前一个 segment 的时长加进下一个 segment 的提示词。

跨 segment 的连续位置由工作台的 `timeline_data.start`、段长度和 `continuityFromPrev` 处理；提示词不能代替这些字段。

### 台词尾部安全线

- 台词开始和结束时间使用当前 segment 的本地时间。
- 普通对白结束后预留约 0.8–1.2 秒，让口型、尾音和收束动作完成。
- 不要把对白安排在 segment 最后瞬间；长对白应先分配足够的说话时间，再安排反应动作。
- 不为了填时长重复对白、重复动作、回放、倒放或新增剧情。

## 固定输出结构

按以下顺序输出：

```text
subject_definitions（主体定义）:
<Subject 1> 是 <Picture 1> 中的场景或角色……
<Subject 2> 是 <Picture 2> 中的角色……
声音设定：
<Picture N> 的说话人用 (S1)/(S2) 标记，并在全片保持一致
detailed_description:
【Shot N｜本 segment 的本地起止秒｜景别·描述】
【主体】……
【动作】……<d>[中文] 台词</d>
【镜头】……
【音效】……
【约束】……
```

如果一个独立 segment 只有一个镜头，也保留 `[Shot N]` 和完整五个子项。

## 主体与参考图

- 角色、场景和关键道具按上传顺序定义 `<Subject N>` 与 `<Picture N>`，后续只引用标签，不反复改写外貌。
- 参考图只锁定被指定的身份、五官、发型、服装或环境，不自动继承参考图表情。
- 没有参考图时不得编造 `<Picture N>`；使用文字主体定义，并写明没有上传参考图。
- 场景定义末尾写清参照范围和白名单，例如：“桌面物品以上述为准，全程不得添加、移动或碰触其他物件。”
- 角色跨 segment 更换时代造型时，明确写出“同一角色、造型切换发生在本段转场后”，并为该段使用对应参考图；不要把现代服装带入古代段。

## Director 事实与连续性规则

### 事件只出现一次

- 每个来源镜头的 `required_events` 必须在对应 `[Shot N]` 中完整出现一次。
- 对白原文必须完整保留一次，不删字、不改字、不用同义句替代。
- `dialogue_owner` 必须与实际说话人一致；双人对白逐句标明说话人，不用一个模糊的 `speaker` 代替。
- 不把上一段已经完成的动作重新演一遍来填时长。

### 起始与收束状态

- 每个 segment 开头先写可见的 `start_state`：人物在哪里、身体姿态、手里有什么、镜头看到什么。
- 每个 segment 结尾写稳定的 `handoff_state`：最后动作完成后人物和关键物件停在哪里。
- 下一段的 `start_state` 必须承接上一段的 `handoff_state`，除非来源明确要求硬切、时空转换或重新开场。
- 交接状态要能被画面看见，不能只写“情绪延续”“气氛一致”。
- 连续段的开头可写“无硬切。紧接上一段。”；来源明确写“硬切”“白光吞没”“时空转换”时，必须保留硬切，不得强行改成无硬切。

## H3 表演与对白

- 台词是动作时间线的一部分，写在【动作】中，不单独列成对白清单。
- 台词格式固定为 `<d>[中文] 原文</d>`。
- 台词前写本地时间、说话人标签、动作和声音信号，例如：

  ```text
  (2.4–4.8秒)<Subject 2> (S1) 先抬眼确认书页，声音压低、语速平稳地说：<d>[中文] 再查查出处，应该还有线索。</d>
  ```

- 情绪靠眼神、呼吸、下颌、肩背、手部和声线表达，不只写“悲伤地说”“紧张地说”。
- 口型必须与 `<d>` 台词同步；台词结束后保留闭口、呼吸或反应动作，不接无关对白。
- 没有对白的镜头明确写“无对白，嘴唇保持闭合”，防止 H3 自行补话。
- 说话人标记与主体定义保持全片一致：`<Picture 1> → (S1)`、`<Picture 2> → (S2)`，不要在后续镜头换标记。

## 镜头动作写法

每个镜头按“接收触发 → 动作变化 → 台词/声音 → 稳定收束”组织：

1. 先写人物看到、听到或触碰了什么。
2. 再写身体动作和镜头变化。
3. 台词放在动作发生的本地时间内。
4. 最后写一个明确可见、能接下一段的姿态。

避免把多个新事件塞进一个短 segment。镜头结束时不要提前执行下一镜的动作。

## 防漂移约束

每个镜头都写简洁的【约束】；至少包含：

- 五官、发型、服装和关键道具位置稳定。
- 口型与台词同步，画面无跳变。
- 不添加未定义人物、物件、字幕、水印或随机文字。
- 同一空间的光线、时间和色调保持一致；硬切时明确写出切换原因。

排除项合并书写，不超过三组，避免与剧情动作冲突。

## 生成前检查

在提交提示词前逐段检查：

1. 该提示词是单 segment 还是多镜头 segment。
2. 若是独立 segment，所有时间码是否从 `0秒` 开始。
3. 每条台词是否完整，结束点是否早于 segment 末尾至少约 0.8 秒。
4. 每个来源事件和对白是否只出现一次。
5. 当前段 `start_state` 是否承接上一段 `handoff_state`。
6. 是否误把硬切写成“无硬切”，或把下一镜动作提前写入当前镜头。
7. `<Picture N>`、`Subject N`、`S1/S2` 是否一一对应。
8. 无对白镜头是否明确禁止补话。

## 推荐交付

普通请求只交付完整提示词和必要的 segment 时长/镜头对应关系，不输出旧版分隔符、不输出隐藏推理、不把技术节点参数暴露成创作选项。用户要求排查时，再说明时间码、交接状态和对白完整性检查结果。
