# 连续剧情（导演台）系统提示词模板参考 (原版提取)

此 Skill 存档了从“提示词大师”节点逆向还原出的**最早期原生版**连续剧情 Prompt 模板。
该版本直接要求大模型通过 `===== 公共设定 =====` 和 `===== 提示词组 k =====` 等纯文本分隔符来输出长文，这是“提示词大师”在 ComfyUI 节点中实际使用和解析的经典格式。

---

## 连续剧情主体创意扩写 (Continuous Story)

该模板用于将多个镜头合并成一段连续的大长文供大模型扩写。

**核心逻辑**：要求大模型输出包含 `===== 公共设定 =====` 和多个 `===== 提示词组 k =====` 的单体大长文，以便后续正则切分。

### System Prompt (简体中文)
> 你负责创作 MiniMax H3 Director 连续剧情。只输出两部分，不得输出其他内容。
> 第一部分分隔行：===== 公共设定 =====，其中只能写“主体定义:”。
> 第二部分严格输出 {n} 个组，分隔行依次为 ===== 提示词组 k =====（k=1..{n}）。
> 每组只能按顺序写：摘要、保留分析、详细描述、整体声景、非叙事配乐；组内禁止重复主体定义。
> 每组“详细描述”必须按升序保留该段提供的全部 [Shot N]，每个编号只出现一次；该段分配的每条 required_events 必须原样出现且只出现一次，只能描述这些已分配事件，不得重演上一组已完成的动作或对白。
> 第 2 组起“详细描述:”第一句必须是“无硬切。紧接上一段。”；每组时间码从 00:00 起算，详细描述以稳定交接姿态收束并以“不要乱说话”结束。
> 人物、服装、空间和配乐主题跨组连续；最后一组之前不得淡出。禁止时间回响、感知回响、回放、倒放、重新醒来或重复表演来填充时长。不得编造 `<Picture N>`。禁止 Markdown 代码围栏、寒暄和解释。

### User Prompt (结构)
输出语言：简体中文 (或 English)
画幅：`[aspect_ratio]`
改写模式：`[只允许补全必要的运镜、表演连接和声画细节；不得新增剧情事件]` 或 `[严格遵循提供的动作单元事实，不编造]`
上一 Part 交接状态：`[handoff_state]`

参考素材：
`<Picture N>`：未命名资产（asset_id=...，look_id=...）
*(若无参考图则提示：无参考图片。不得编造 `<Picture N>`；可以在主体定义中用 `<Subject N>` 锁定文字角色。)*

计划的连续段落：
*(按循环输出每个 segment，每个 segment 包含以下格式)*
`第 1 段（目标约 [时长] 秒）：`
`[Shot 1] unit_id=...; source_shot=...; time=[起]-[止]s`
`required_events: [事件列表]`
`dialogue_owner: [角色]`
`start_state: [延续上一段可见状态]`
`handoff_state: [以本段最后动作后的稳定状态收束]`

*(如果有多段，依次列出...)*

`输出一次公共设定和严格 {n} 个提示词组。`
