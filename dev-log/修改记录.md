### 画布参考图缩略图空白：带目录的 /api/media 路径落到 SPA 兜底

- **功能模块**：无限画布 / 生成节点创作面板（参考图缩略条）
- **修改原因**：从图片节点拉出下游生成节点后，创作面板「参考图 1」只显示占位/破图，而源节点自己可以正常显示。实测该节点 `resultPath=zly-ai-video-studio/minimax_h3_image/20261119/xxx.png`，前端按 `encodeURIComponent` 生成 `/api/media/...%2F...`；媒体路由只声明了 `/api/media/{filename}`，解码后的斜杠导致路由不匹配，请求落到前端 SPA 兜底，返回 200 + `text/html`，`<img>` 解码失败即表现为空白。
- **实现思路**：
  1. `backend/app/main.py`：媒体路由改为 `/api/media/{filename:path}`，带目录的输出路径按媒体字节返回。
  2. `backend/app/main.py`：未匹配的 `/api/**` 在 SPA 兜底前直接 404，避免把 HTML 当作媒体静默成功。
  3. `frontend/src/canvas/canvas-generation.ts`：新增 `canvasReferencePreviewUrl`，缩略图优先使用节点自身正在显示的地址（生成结果下载地址 / 素材云地址），再回退同源 `/api/media` 路径；提交读取仍用 `canvasReferenceUrl`（同源素材路径优先）。
  4. 回归用例：`backend/tests/test_read_caches.py` 覆盖带目录路径返回媒体字节、缺失路径 404 与未知 API 404；`frontend/src/canvas/canvas-generation.test.ts` 覆盖缩略图与上传地址的不同优先级。
- **验证**：live 请求 `/api/media/zly-ai-video-studio%2Fminimax_h3_image%2F20261119%2F...png` 由 `200 text/html` 变为 `200 image/png`（12.7 MB），`/api/definitely-missing` 返回 404；5173 实测画布 `canvas_299d984bd0ec4b20a2a0c4ea`，创作面板参考图 1 的 `<img>` 指向 `/api/jobs/.../outputs/0/download`，`naturalWidth=2304 / naturalHeight=4096` 已加载；`pnpm --dir frontend build` 与 `pytest backend/tests/test_read_caches.py` 通过；后端全量 2205 项通过，另有 6 项既有失败（openapi 文档缺口、director stream、enterprise、guest catalog、media schema、media understanding），与本次改动无关。
- **回滚**：把媒体路由恢复为 `/api/media/{filename}` 并移除 SPA 兜底的 `/api` 404 分支；前端删除 `canvasReferencePreviewUrl` 并让 `CanvasGeneratorComposer` 继续直接用 `canvasReferenceUrl`。

### 修复 MiniMax 官方 H3 参考图生视频缺省 ratio（官方 2013 拒单）

  2. `cloud_video/minimax.py`：显式 ratio 一律校验下发；参考图场景缺失 ratio 时提交前抛 `CloudVideoError`，不再把必败请求发上游。
  3. 测试：`test_cloud_video.py` 同步 2 处旧断言，新增 `test_minimax_h3_r2v_defaults_explicit_ratio`。
- **验证**：`python -m unittest backend.tests.test_cloud_video` 60 项通过；真实出片 `F5QlctjeMqLL` 成功（约 2 分 10 秒，ffprobe 1344×768 / 24fps / 12.25s / 294 帧 / 无音轨）。
- **影响范围**：仅 `cloud-minimax-h3-r2v`；t2v/i2v/fl2v 与其它云端工作流请求体不变。

### 无限画布助手兜底缺陷修复（GUI 黑盒测试后）

- **功能模块**：无限画布 / 智能助手（前后端）
- **修改原因**：以纯新手视角自动化测试助手发现 6 项缺陷——超长输入发送无反馈且错误文案带技术字段名（D1）；首条消息发送失败后空会话「三空」无引导（D2）；应用方案后 Ctrl+Z 撤销，方案卡仍显示「已应用」与画布不一致（D3）；方案卡与错误信息泄漏内部节点 ID（D5）；批量删除（>24 ops）提案格式校验失败后重试陷入同模型死循环（D4）；发送失败的错误提示会被会话恢复 effect 的 `setError("")` 静默抹掉，新手看到「点了发送毫无反应」（D6 现象的确认根因）。另确认 D7（关闭面板重开会话丢失）为测试误报：坐标点击误触「新对话」，正确点击时关闭重开会话完整保留。
- **实现思路**：
  1. `frontend/src/canvas/assistant/CanvasAssistantPanel.tsx`：`send()` 补上缺失的 `setSending(true)`（POST 期间立即禁用输入防重复）；发送成功后校验 run 的 `user_message_id` 确实出现在刷新后的会话里，否则报「消息可能未保存成功」并保留输入（D6 兜底）；`errorText` 把 50000 字校验错误翻译为新手可读文案（D1）；空会话（含首条发送失败后）保留欢迎页引导（D2）；会话恢复 effect 不再无条件 `setError("")`，避免误清发送失败提示，错误只由用户关闭或下次发送成功覆盖；404/403 自愈时才清空。
  2. `frontend/src/canvas/assistant/assistant-bridge.ts`：应用结果新增 `created_node_ids` / `removed_node_ids`（撤销检测依据）；所有错误文案去除内部节点 ID 并给新手可执行指引（D5）。
  3. `frontend/src/canvas/assistant/proposal-card.tsx`：已应用方案卡每 2s 对照画布现状——新建节点全部消失或被删节点全部重现时显示「已被画布撤销」并提供「重新应用到画布」，部分不一致显示提示（D3）。
  4. `frontend/src/canvas/CanvasEditor.tsx`：bridge 增加 `filterMissingNodeIds`；`describeNode` 增加只增不减的节点标题缓存，节点被删后仍显示标题而非 ID（D5）。
  5. `backend/app/canvas_assistant/service.py`：`_parse` 在 JSON 结构层提前识别提案 ops 超 24 上限，抛出带拆分指引的 `_ActionableFormatError` 并在两级兜底 except 中原样穿透（不替换为泛化格式错误），修复轮模型因此能看到「只保留前 24 个并说明剩余部分」的可执行指令（D4）。
  6. `backend/app/canvas_assistant/protocol.py`：JSON 与原生两份系统提示词补充「单个提案硬上限 24 ops，批量操作只出前 24 个并说明剩余」规则。
- **兼容性**：无 API/数据库/协议结构变更；`apply_result.detail` 新增 `created_node_ids` / `removed_node_ids` 字段为纯增量，旧数据（无这两个字段）按空数组处理不触发检测。
- **验证命令**：`cd frontend && npx vitest run`（1109 通过，含 assistant.test.ts 23 例）；`python -m unittest backend.tests.test_canvas_assistant`（33 通过，含新增 `test_parse_oversized_proposal_gives_actionable_error`）。桌面端浏览器回归：发送即禁用、超长 400 友好提示+欢迎页保留+草稿保留、22 节点删除方案应用→撤销→「已被画布撤销」+「重新应用到画布」→重新应用闭环、删除明细显示节点标题。
- **回滚方式**：还原上述 7 个文件（canvas_assistant 两文件为未跟踪新文件，直接还原内容）即可；无数据迁移。
